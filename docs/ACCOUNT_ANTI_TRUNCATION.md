# 账号模型抗截断

在「账号管理 → 创建 / 编辑账号 → 账号模型抗截断」中添加规则，填写需要开启的客户端模型名或别名。规则按名称精确匹配，不支持通配符。同一上游模型可以有一个普通别名和一个开启抗截断的别名。

账号保存新规则后由账号配置接管：未匹配的模型关闭，清空规则关闭整个账号的抗截断。尚未保存账号规则的旧账号继续兼容原分组配置；分组中的模型别名仍可正常使用。批量编辑可选择保持不变、设置规则或全部关闭。 同一分组有多个账号时，按每次实际选中的账号决定是否续写。若希望整个号池的同一别名都启用，可为所有会承接该别名的账号批量设置同名规则。

## 规则参数

| 参数 | 行为 |
| --- | --- |
| 最大续写轮数 | 默认额外续写 1 次，最多 3 次；不包含首轮。 |
| 累计输出预算 | 默认 0，不增加额外输出限制。客户端明确传入的输出上限仍然保留。 |
| 续写时间预算 | 默认 180 秒，最多 300 秒。从首次需要续写时开始，只决定是否启动下一轮，不取消正在生成的请求。 |

本功能不移除模型或上游自身的输出限制，也不保证模型一定遵从续写指令。请优先将累计输出预算保留为 0；单独设置预算时，它会限制是否继续以及后续轮次的剩余输出额度。

## 触发条件与协议

Chat Completions、Messages、Gemini / Vertex、反重力和 Responses HTTP 均支持安全文本的流式与非流式续写。Responses WebSocket 也支持安全文本续写。

只有已经产生有效正文，并出现输出上限截断或可安全恢复的缺少结束标记断流，才会续写。正常结束、空回复、拒绝、安全拦截、用户取消不续写。工具调用、图片音视频、签名或加密推理、多候选、结构化输出以及依赖外部会话状态的请求保留原转发行为。含此类内容的输出也会停止自动续写，避免重复调用工具或破坏状态。

流式续写沿用一次客户端响应，正文连续下发；非流式合并各轮正文。原生 Responses 保留一个公开响应 ID，并在原用户和分组权限范围内关联最后一个真实上游响应，供后续会话请求使用。

## 费用与记录

每轮会重新携带上下文，因此可能增加输入费用。每轮分别恢复实际用量并按该轮价格阶梯计费，最后合并为一条逻辑使用记录，不将多轮合计输入误套成单轮长上下文价格。

失败且没有实际下发有效输出的轮次不扣用户费用；部分正文已经下发后中断，该轮输入沿用原计费口径，输出只按已下发部分计费。上游真实成本独立记录。内部审计仅保留有界的标量用量、模型和请求标识，不保存提示词、正文或凭据，不通过普通使用记录接口公开。

## 管理接口存储格式

账号创建、编辑及批量编辑沿用现有 `extra` 字段：

```json
{
  "anti_truncation": {
    "version": 1,
    "rules": [
      {
        "model": "long-text-alias",
        "enabled": true,
        "max_rounds": 1,
        "max_output_tokens": 0,
        "max_duration_seconds": 180
      }
    ]
  }
}
```

名称优先匹配客户端原始别名，其次匹配账号映射前的路由模型；不会根据最终上游模型反向开启其他别名。

发布需要迁移 `262_continuation_usage_audit.sql`。含续写审计的持久结算任务使用 outbox v5；所有活跃消费者必须支持新格式后才能启用，旧消费者应拒绝并保留未知版本任务。与分类默认分组审计同时出现时保留 v5，普通分类入口记录仍使用 v4。
