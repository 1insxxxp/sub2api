# 空回申请当前页一键多选设计

## 背景

空回申请后台已经支持逐条勾选后批量通过或驳回，并会在翻页时保留已选择的申请。但桌面表头和移动端都没有一键选择入口，管理员需要逐条勾选；同时终态申请也能被选中，批量提交时才会失败。

## 方案比较

1. **全选当前页全部记录**：实现简单，但会把已补偿、已驳回等不可审批记录一起选中，批量操作容易产生无意义失败。
2. **全选当前页可审批记录（采用）**：只选择 `evaluating`、`manual_review`、`approved` 状态，兼顾效率与安全，也不需要修改后端接口。
3. **全选全部筛选结果**：可以跨分页批量处理，但需要服务端保存筛选快照或提供按筛选条件批处理接口，误操作影响范围也更大，本次不采用。

## 交互设计

- 桌面端在表格复选框列的表头增加复选框。
- 当前页可审批记录全部选中时显示选中状态；部分选中时显示半选状态；再次点击取消当前页可审批记录的选择。
- 移动端在筛选操作栏增加“全选当前页/取消全选”按钮，并显示当前已选数量。
- 不可审批记录的复选框禁用，避免用户误以为可以进行批量审批。
- 翻页时保留其他页面的已选记录；当前页的全选/取消全选只修改当前页可审批记录，不清除其他页选择。
- 刷新、切换状态筛选或日期范围时沿用现有行为，清空选择，避免对已变化的数据继续操作。

## 数据流与边界

- `selectableClaims` 从当前页 `claims` 中筛选可审批记录。
- `allPageSelected` 和 `somePageSelected` 根据 `selected` 集合派生。
- `togglePageSelection` 复制现有 Set，批量添加或删除当前页可审批 ID，再整体替换响应式引用。
- 页面没有可审批记录时，全选控件禁用。
- 单条选择仍使用现有 `toggleSelected`；不可审批记录不进入选择集合。

## 测试

- 一键选择当前页所有可审批记录，并排除不可审批记录。
- 再次点击取消当前页选择。
- 部分选中时桌面表头呈半选状态。
- 翻页后保留其他页选择，取消当前页不会清掉其他页记录。
- 移动端按钮与桌面表头调用同一选择逻辑。
