# 可用渠道分组模型展示定价回填设计

## 背景

“可用渠道”先从渠道的模型映射与渠道定价生成 `SupportedModels`，再按分组当前可调度账号补充实际可用模型。当某个模型只出现在分组可用模型中、尚未出现在渠道映射或渠道定价中时，现有转换逻辑会返回 `pricing: null`。即使全局 LiteLLM 价格库已经收录该模型，前端仍显示“未配置定价”。

## 目标

仅修复用户侧“可用渠道”的展示定价：渠道自定义定价优先；分组额外补充的模型若没有渠道定价，则使用全局价格库生成展示定价。真实计费仍由现有计费解析链路负责，不因本修复发生变化。

## 方案

在 `ChannelService` 增加一个只读的展示定价查询方法，复用现有 `PricingService.GetModelPricing` 与 `synthesizePricingFromLiteLLM`。`AvailableChannelHandler` 在把分组模型 ID 转成用户 DTO 时：

1. 先按平台和模型名查找渠道已有的 `SupportedModel`，命中时原样保留渠道定价。
2. 未命中时调用展示定价查询，从全局价格库合成 `ChannelModelPricing`。
3. 全局价格也不存在时继续返回 `pricing: null`。

查询只在用户打开“可用渠道”页面时发生，不写数据库、不填充渠道配置，也不进入请求计费热路径。

## 测试

- 分组模型不在渠道列表、但全局价格库有价格时，响应包含回填价格。
- 渠道已有自定义定价时，自定义价格优先且不被全局价格覆盖。
- 渠道和全局均无价格时，响应仍为 `pricing: null`。
