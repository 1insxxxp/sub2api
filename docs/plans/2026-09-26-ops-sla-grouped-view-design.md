# 运维 SLA 分组定位视图设计

## 背景

运维面板的 SLA 卡片可以显示最终失败率，但目前只能打开逐条错误明细。排查 SLA 降低时，需要手动从大量记录中判断哪些分组、模型和账号受影响；上游错误分组定位已有清晰的表格结构，但它统计的是上游尝试错误，不能直接代表用户最终看到的失败。

## 目标

- 在 SLA 卡片的“明细”旁增加“分组定位”入口。
- 使用当前运维面板的时间范围、平台、分组和错误筛选条件。
- 按分组、模型、失败类型、受影响账号聚合最终计入 SLA 的失败请求。
- 复用上游分组定位的密集表格样式，分组默认展开，第一屏能看到分组、模型、账号、次数、状态码和最新时间。
- 从聚合行打开现有错误详情，继续查看脱敏后的错误内容和请求上下文。

## 统计口径

只纳入最终计入 SLA 的错误请求：最终状态码为 400 或以上，且未标记为业务限制。恢复成功的上游尝试、429/529 上游限流遥测和余额/配额等业务限制不进入 SLA 定位面板；这些记录仍由对应的上游错误或业务限制视图处理。

## 非目标

- 不改变 SLA、上游错误或错误日志的写入和计算逻辑。
- 不修改现有错误明细和错误详情接口的返回字段。
- 不返回未脱敏的请求体、密钥或上游地址。
- 不新增独立运维页面，只在现有 SLA 卡片和错误详情流程中增加入口。

## 交互与界面

在 `OpsDashboardHeader` 的 SLA 卡片操作区保留“明细”，旁边增加“分组定位”。点击后打开新的 SLA 分组定位弹窗，弹窗沿用 `OpsUpstreamErrorSummaryModal` 的宽度、表格密度、材质和加载/错误/空状态。

弹窗内容为分组表格：

1. 顶部显示错误总数、分组数和最近时间，并保留当前筛选上下文。
2. 每个分组默认展开，显示分组错误数、模型数、账号数和最近时间。
3. 表格行显示模型、失败类型、账号、错误原因摘要、最终状态码、次数、最新时间和详情操作。
4. 账号、模型和原因名称允许换行；移动端保持横向可滚动表格，避免压缩成难以阅读的卡片。
5. 详情操作复用现有错误详情弹窗，代表错误 ID 指向同一条最终失败记录。

## 后端接口与数据流

新增管理员接口 `GET /admin/ops/request-errors/summary`，参数沿用错误明细筛选（时间范围、自定义时间、平台、分组、模型、关键词、状态码和视图）。接口由独立的 repository/service 查询实现，避免复用上游 provider 条件。

返回结构与 `OpsUpstreamErrorSummary` 对齐，包含总错误数、分组数、最新时间、分组列表和截断标记。分组下的模型、账号和原因字段保持同名结构，原因节点增加最终失败的错误类型、状态码、次数、最新时间和代表错误 ID。查询在数据库完成聚合和排序，结果上限与上游汇总一致，超出时返回截断标记但保留总数。

`OpsDashboard` 负责弹窗状态和筛选参数，`OpsDashboardHeader` 负责入口，SLA 汇总弹窗复用上游汇总表格的展示逻辑；API 类型和测试分别补充 request-errors summary 的请求与响应。

## 错误处理与性能

- 无数据返回零计数和空分组，显示现有空状态。
- 汇总请求失败时保留弹窗和筛选条件，显示重试按钮，不影响 SLA 卡片和普通错误明细。
- 接口只返回聚合后的脱敏摘要和代表 ID，避免把完整错误正文一次性载入。
- 复用现有时间范围校验、监控开关和查询索引；默认不读取分页参数，避免只聚合当前页。

- 前端测试 SLA 入口、参数传递、加载/错误/空状态、默认展开、详情跳转和移动端表格渲染。
