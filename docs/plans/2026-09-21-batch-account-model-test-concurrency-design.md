# 一键模型测试全量并发设计

## 目标

一键测试当前账号的全部可测试模型时，同时发起所有模型探测，缩短总耗时；每个模型仍独立显示成功、失败、错误信息和端到端耗时。

## 方案

继续复用现有 `POST /api/v1/admin/accounts/:id/test` SSE 接口，不新增后端批量路由。前端批量调度器为当前模型快照创建一个请求任务，并通过 `Promise.all` 并发执行全部任务。每个任务使用独立模型参数和共享批量 `AbortController`，互不阻塞；某个任务失败不会影响其他任务。

这是当前账号模型数量较少、用户明确希望一次性探测的场景。并发只作用于管理员弹窗的批量测试，不改变单模型测试和普通请求的并发控制。

## 状态与取消

批量开始时所有结果先置为 `pending`，每个任务启动时置为 `testing`，完成后置为 `success` 或 `failed`，并记录自己的耗时。关闭弹窗或点击停止时中止共享控制器，把仍处于 `pending`/`testing` 的结果标为 `cancelled`；已经完成的结果保留。

## 兼容性与风险

后端测试接口会为每次测试更新账号错误/限流状态。由于用户确认每个账号模型数量少并要求全量并发，接受同一账号多个测试完成顺序导致的最后状态覆盖风险；不修改生产状态模型，也不影响真实请求路径。

## 验证

- 组件测试验证所有模型请求在首个响应完成前已经发起。
- 组件测试验证混合成功/失败结果、每项耗时和失败继续保留。
- 组件测试验证停止时所有进行中的请求被取消并标记为取消。
- 运行该组件测试、相关类型检查和 ESLint。
