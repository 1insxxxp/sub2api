# 渠道监控移动端卡片布局设计

## 问题

渠道监控 V2 的可用性矩阵在桌面端使用六列 CSS Grid。移动端媒体查询却只声明四列，吞吐开启时成功率、首 Token、每秒 Token、缓存率和时间色块会进入隐式网格并错行。分组列同时被压缩到 88px 且使用 `truncate`，因此手机端只能看到 `anthropic / ...`，无法辨认分组。

## 目标

- 640px 以下把每个渠道维度显示为独立卡片。
- 第一行完整显示“平台 / 分组名 / 模型”，允许自然换行与任意长文本断行。
- 第二行显示成功率、首 Token、每秒 Token（如允许展示）和缓存率的带标签指标网格。
- 第三行让时间状态色块占满卡片宽度；只有放大后的色块轨道允许横向滚动。
- 保持桌面端六列表格、健康颜色、隐私裁剪、缩放和 tooltip 行为不变。

## 组件结构

`RelayPulseMatrix.vue` 继续复用同一份 `alignedRows` 数据，不创建第二套数据流。桌面表头在移动端隐藏；每个 `.matrix-row` 在移动端改为三段式网格：`.dimension-cell`、`.mobile-metrics`、`.pulse-track-shell`。桌面指标节点保持现有结构，移动端通过同一数值函数渲染带标签的指标，避免 CSS 对未知数量子节点自动排版。

分组名称节点移除移动端截断，使用 `white-space: normal`、`overflow-wrap: anywhere`。桌面仍保留单行截断和 `title`。

## 交互与可访问性

- 卡片名称始终可读，长名称不撑破视口。
- 色块继续支持键盘聚焦、原生 `title`、悬停与浮动 tooltip。
- 移动端卡片不劫持页面纵向滚动；只有已放大的时间轨道产生横向滚动。
- 指标标签使用现有中英文文案，不改变后端协议。

## 测试

- 先新增失败测试，要求存在移动端卡片语义节点、完整名称节点和四项带标签指标。
- 静态结构测试锁定移动端 CSS 不再把六个子节点放入四列网格。
- 运行 Channel Monitor V2 全部前端测试、两套类型检查、lint 和生产构建。
- 在本地服务以约 390px 视口打开真实页面，确认名称可见、页面无横向溢出、色块与 tooltip 可用。
