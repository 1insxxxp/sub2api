# 分组模型别名与抗截断策略设计

## 目标

在同一个分组内增加可选的公开模型别名。别名请求仍使用原分组的账号池、协议和计费配置，但将请求转发到管理员指定的上游模型，并可以只为这个别名开启抗截断续写策略。原始模型名称继续按现有逻辑工作，不被别名配置改变。

## 配置模型

分组增加 `model_aliases` JSON 配置。每条记录包含：

- `alias`：新增的客户端模型 ID，必须唯一，不能与其上游模型或其他别名的目标重名；不要覆盖已有模型名。
- `upstream_model`：实际发送给上游的模型 ID。
- `anti_truncation.enabled`：是否允许在确认输出被截断后自动继续。
- `anti_truncation.max_rounds`：开启策略后首轮之外最多继续的轮数，留空或 0 使用默认 1，最大 3。
- `anti_truncation.max_duration_seconds`：整个请求（包括首轮）的时间上限，留空或 0 使用默认 180 秒，最大 300 秒。
- `anti_truncation.max_output_tokens`：可选的累计输出上限，留空或 0 表示不额外限制，仍受上游和请求本身限制。

配置写入分组 JSONB，不放在账号凭据里，也不复用渠道级 `model_mapping`。这样别名只对绑定该分组的 API Key 生效，并且不会改变其他分组使用同一上游模型的行为。认证缓存、管理员 DTO 和分组复制都必须完整透传该字段。

## 请求流程

1. 认证后从分组快照解析客户端请求的模型 ID。
2. 如果命中别名，保留原始请求模型用于访问控制、使用记录和客户端响应，把 `upstream_model` 作为调度和上游请求模型；未命中时沿用现有路径。
3. 公开模型列表在现有可用模型基础上加入目标可用且通过白名单的别名；保留原模型，不因别名额外暴露内部目标。
4. 渠道级映射继续在别名解析之后执行，最终上游模型仍以现有渠道/账号映射规则为准。模型映射链记录为“别名→渠道映射→实际上游模型”，原始模型没有别名时保持旧格式。

## 抗截断状态机

抗截断只对命中的别名生效，默认关闭。每一轮使用同一个已选账号和会话上下文，避免跨账号丢失原生思维链、签名或工具状态。

- 正常终止（`stop`、完成事件、客户端取消、内容安全拒绝、4xx 或空响应）直接结束，不自动续写。
- `finish_reason=length` 或已经产生语义输出后上游提前结束，且当前轮数、总时间和累计输出预算仍未超限时，启动下一轮。
- 续写请求追加上一轮已经确认的助手输出，并使用固定的继续提示；工具调用、结构化输出、加密思维链或无法安全重建上下文时不续写，返回现有错误语义。
- 达到任一预算后，保留已收到内容并按现有截断错误/结束事件收尾，不能无限重试。

首期实现覆盖 OpenAI Chat Completions 直转、Anthropic Messages→Chat 兼容桥，以及 Chat 客户端→Anthropic Messages 上游的转换路径。这些路径具备可观察的增量文本和可重放的消息数组。原生 Responses/WebSocket、原生 Anthropic 直转、Gemini/Antigravity 路径暂只使用别名映射，不改变现有流状态机。所有已接入的路径保留客户端别名和实际上游模型。

## 计费与记录

- 每一轮的上游 usage 累加后只提交一次使用记录，避免重复扣费。
- 计费默认继承目标模型，分组/渠道为别名显式定价时优先采用该价格；别名本身不增加倍率，续写产生的真实 token 会自然计入。
- 使用记录保留客户端请求别名、渠道映射链、最终上游模型、续写轮数和是否触发抗截断。
- 续写过程中的中间轮不单独产生客户端可见的终止事件，也不单独记为失败。

## 管理端交互

在分组编辑的模型白名单/模型配置区域增加“模型别名”列表：可新增、编辑、删除别名，填写上游模型，并通过开关展开抗截断参数。保存时校验别名格式、重复项、上游模型不能为空，参数范围与后端保持一致。原有模型白名单和渠道映射界面保持不变。

## 测试边界

- 配置规范化、范围校验、分组复制和认证快照往返。
- 命中/未命中别名时的模型解析、模型列表展示和映射链。
- 抗截断只在别名开启时触发；正常停止、客户端取消、4xx、工具调用和超出预算不触发。
- 多轮 usage 累加、单次计费提交、别名与上游模型记录。
- 现有无别名请求的路由、计费和流式结束行为回归测试。
