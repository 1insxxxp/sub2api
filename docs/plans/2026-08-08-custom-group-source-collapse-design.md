# 自定义分组来源折叠设计

## 背景

自定义分组的新建和编辑表单会直接展开所有来源分组及其模型。来源分组较多时，用户需要滚动很长距离才能定位目标分组，移动端尤其不便。

## 目标

- 进入新建或编辑表单时，所有来源分组默认折叠。
- 用户可以点击来源分组标题单独展开或收起。
- 用户可以一键展开全部或折叠全部来源分组。
- 折叠状态下仍能看见来源分组的平台、模型总数和已选模型数。
- 保留现有模型选择、调用名称编辑、校验、保存和计费语义。

## 交互设计

每个来源分组显示为一个可折叠卡片。卡片标题占满可点击区域，包含：

- 来源分组名称；
- 平台标签；
- “N 个模型”；
- 该组存在选择时显示“已选 N”；
- 指示当前展开状态的箭头。

点击标题切换当前卡片。标题使用原生按钮并提供 `aria-expanded` 和关联内容区域，键盘和触屏均可操作。移动端触控高度不低于 44px。

“选择模型及来源”标题右侧保留总已选数量，并新增“全部展开 / 全部折叠”操作。只要存在未展开分组就显示“全部展开”；全部已展开时显示“全部折叠”。

新建、编辑、保存后再次进入表单时均重置为全部折叠。编辑已有分组时，不自动展开已选来源，仅通过“已选 N”提示帮助定位，避免来源很多时再次产生长页面。

## 状态与数据

组件新增 `expandedSourceIds: Set<number>` 保存本次表单会话的展开来源 ID。该状态仅属于界面展示，不进入 API 请求，也不持久化。

- `startCreate`：清空集合；
- `startEdit`：清空集合；
- `backToList`：无需保留；
- 单组切换：复制集合后添加或删除来源 ID；
- 全部展开：用当前候选来源 ID 创建集合；
- 全部折叠：清空集合。

每组已选数从现有 `selected` 映射实时计算，不建立第二份可变状态。

## 响应式与视觉

沿用项目现有浅色/深色边框、徽章和按钮体系。折叠卡片头在窄屏允许信息换行，但箭头固定在右侧；模型网格保持当前单列、超宽屏双列布局。展开内容使用轻量分隔线，不添加嵌套弹窗。

## 测试

组件测试覆盖：

- 来源分组内容受展开状态控制，初始状态为空；
- 新建和编辑入口都会重置展开状态；
- 单组切换函数添加/移除来源 ID；
- 全部展开/折叠操作存在；
- 卡片标题包含 `aria-expanded`、模型数量和已选数量。
