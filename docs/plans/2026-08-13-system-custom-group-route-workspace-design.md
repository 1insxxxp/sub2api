# 系统自定义分组路由工作区设计

## 目标

让“模型路由”成为创建/编辑自定义分组时的主要操作区域，同时降低批量选择成本，并准确说明跨协议来源的调用边界。

## 交互设计

- 对话框使用最大宽度，名称与默认有效期保持常驻。
- 描述和共享订阅配额收进“更多设置”，创建时默认收起；编辑已有高级配置时自动展开。
- 模型路由工作区占据主要可视高度，左右栏继续独立滚动。
- 顶部保留“全选全部”，每个来源分组标题增加三态“全选本组”和已选/总数。
- 每个来源分组可独立展开或折叠；折叠只隐藏模型行，保留名称、协议、选择统计和批量选择，且不改变路由草稿。
- 同时选择多种协议来源时显示提示：兼容接口会按来源转换，Gemini 原生接口只允许 Gemini 来源。

## 协议语义

系统自定义分组允许混合来源平台，这是“一把 Key 使用所有酒馆渠道”的核心能力。每个公开模型绑定一个固定来源分组和来源模型，不在不同来源间自动降级或改路由。

- `/v1/messages` 等 Claude/OpenAI 兼容入口会根据来源平台选择对应处理器；Gemini 来源可通过兼容层完成协议转换。
- Gemini 原生 `/v1beta` 入口只接受 Gemini 来源，选择 Anthropic/OpenAI 来源时应拒绝。
- Live、WebSocket 等未支持系统路由的端点继续 fail closed。

## 验证

- 组件测试覆盖每组全选/半选/取消、全局全选互不误伤。
- 组件测试覆盖单组折叠互不影响、草稿保持，以及顶部导航自动展开目标分组。
- 组件测试覆盖主工作区尺寸、更多设置与跨协议提示。
- 后端真实路由测试覆盖系统 Key 经 `/v1/messages` 路由到 Gemini 来源并成功返回 Claude 兼容响应。
