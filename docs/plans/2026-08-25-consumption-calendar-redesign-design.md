# 消耗日历 UI 重构设计

## 背景

当前消耗日历只在日期单元格中显示日期和状态标记，流水与收益需要查看日历下方摘要或桌面右侧区域。移动端空间有限，日期摘要和明细区域容易被挤压，用户无法快速判断每天的消耗和收益。

## 目标

- 在每个有数据的日期单元格中直接展示当日余额消耗和收益金额。
- 点击日期后打开日期明细弹窗，查看分组汇总和可展开的请求流水。
- 桌面端使用居中弹窗，移动端使用底部弹窗，保证内容可滚动且不破坏日历布局。
- 保留现有 API 数据结构和分组/请求分页能力，避免不必要的后端变更。

## 方案

采用单一响应式明细弹窗方案。`SubAdminCommissionCalendar` 负责月度摘要、日期网格和打开日期事件；`SubAdminCommissionPanel` 管理当前选中日期；`SubAdminCommissionDayDrawer` 重构为响应式弹窗并继续负责日期分组、请求日志和分页。

### 日历单元格

- 日期数字作为主信息。
- 有消耗或收益时，在日期下方显示两行金额：`消耗 $xxx` 和 `收益 $xxx`。
- 金额使用紧凑格式避免撑破单元格，完整值通过 `title` 和 `aria-label` 保留。
- 当前选中日期使用蓝色边框/浅色底，已有数据日期使用轻量状态标记。
- 移动端使用更紧凑字号和最小高度，桌面端适当放大金额层级。

### 明细弹窗

- 日期为空时不渲染。
- 桌面端：固定遮罩、居中卡片、最大高度滚动，宽度随视口限制。
- 移动端：贴近底部的圆角抽屉式弹窗，最大高度约为视口 90%，内容区独立滚动。
- 顶部展示日期、当日消耗和收益，关闭按钮固定在标题区。
- 分组卡片显示分组名称、请求数、Token、消耗、收益；请求日志维持当前展开/折叠和分页行为。
- 支持点击关闭按钮、遮罩和 Escape 关闭；弹窗打开时禁止背景滚动，关闭时恢复。

### 数据流

1. 月份变化时调用现有 `getWorkbenchCalendar`。
2. 点击有数据日期时由日历向面板发出 `select-day`。
3. 面板将日期传给明细弹窗；弹窗调用现有 `getWorkbenchDayGroups`。
4. 展开分组后调用现有 `getWorkbenchDayGroupLogs`，分页参数保持不变。
5. 月度汇总继续由日历接口返回的每日数据计算。

## 错误处理与可访问性

- 保留加载、错误和空数据状态，均在弹窗内部展示。
- 日期按钮使用包含日期、消耗和收益的完整 `aria-label`。
- 弹窗使用 `role="dialog"`、`aria-modal="true"` 和可读标题。
- 关闭按钮有明确标签；Escape 和遮罩关闭不影响已加载数据。

## 验证范围

- 更新现有日历组件测试，验证日期格金额、紧凑布局和选中状态。
- 验证点击日期显示响应式明细弹窗，分组展开仍能加载请求日志。
- 验证移动端 class、弹窗滚动容器和关闭行为。
- 运行相关 Vitest 测试及前端构建。
