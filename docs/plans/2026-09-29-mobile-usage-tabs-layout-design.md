# 移动端使用记录页签与布局统一设计

## 背景

移动端使用记录页的三个页签（用量明细、错误请求、空回列表）当前在不同状态下存在对齐、间距和顶部占位不一致的问题。需要沿用 API 密钥页已确认的中性半透明材质、紧凑工具栏和品牌蓝选中态，让用户更快进入记录列表。

## 设计目标

- 三个页签在移动端使用等宽、紧凑的分段控件，选中态明确但不过度装饰。
- 缩小统计卡片、时间筛选和粒度选择之间的垂直空白，减少首屏无效占位。
- 三个页签共享一致的筛选网格、字段标签、选择器和操作按钮尺寸，切换页签时不产生明显跳动。
- 继续保留桌面端现有布局和信息密度，不改变接口、权限、计费或记录数据逻辑。
- 与浅色、深色主题和减少动态效果设置兼容。

## 方案

### 页签

保留现有 `usage-record-tabs` 语义和按钮交互，移动端改成三等分的紧凑分段控件：外层使用 API 密钥页风格的中性控制面板，按钮拥有稳定的最小高度和等宽布局；选中按钮使用品牌蓝底色、白色文字和轻微内阴影，未选中按钮保持透明或浅色控制底。桌面端继续使用现有底部指示线页签。

### 顶部区域

仅在移动端收紧 `UsageStatsCards` 的卡片间距、卡片内边距和文字层级间距；时间范围和粒度选择沿用已有字段，但采用统一的紧凑控制高度和较小的上下留白。现有“统计分析”折叠入口保持在记录列表之后，避免重新引入大块图表占位。

### 筛选与操作区

移动端筛选继续使用两列网格，统一每项标签高度、选择器高度和列间距；空回列表没有筛选项时，说明区保持紧凑。刷新、重置、列设置等图标按钮使用一致的 40px 触控尺寸，导出按钮沿用主要操作样式并在可用宽度内对齐。错误请求和空回列表的内容卡片不增加额外外框。
