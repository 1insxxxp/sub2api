# 抽奖余额到账与兑换页记录设计

## 背景

抽奖中奖的余额已经在抽奖事务中写入 `users.balance`，但用户兑换页的“最近活动”只读取兑换码历史（`redeem_codes`），因此抽奖余额奖励不会出现在该列表中；抽奖完成后前端账户缓存也不会立即刷新。

## 目标

1. 抽奖成功后立即刷新当前用户信息，使顶部余额和后续页面显示最新余额。
2. 在兑换页最近活动区域展示抽奖获得的余额奖励，并明确标记为抽奖奖励。
3. 继续使用现有 `lottery_draws` 作为中奖记录来源，不创建伪造兑换码、不重复增加余额、不修改数据库结构。

## 方案

- `LotteryView` 在抽奖接口成功后调用 `authStore.refreshUser()`；刷新失败只记录日志，不覆盖已经成功的抽奖结果。
- `RedeemView` 并行加载兑换历史和 `/lottery/history`，筛选 `prize_type=balance` 的中奖记录，单独渲染“抽奖余额奖励”卡片。抽奖历史接口失败时保留兑换历史正常显示。
- 抽奖奖励记录沿用中奖快照中的金额和时间，前端不要求兑换码字段，避免把抽奖记录误当成可兑换码。

## 错误处理

- 抽奖请求成功但用户信息刷新失败：保留中奖结果，提示不变；余额可通过页面刷新或自动刷新恢复显示。
- 兑换页任一历史接口失败：另一历史列表仍可用；抽奖奖励区域显示空状态或隐藏，不影响兑换功能。

## 测试

- 用户抽奖视图：余额中奖后调用 `refreshUser`。
- 兑换视图：渲染余额型抽奖记录并显示金额；非余额型抽奖记录不混入余额奖励列表。
- 保留现有兑换和抽奖 API 契约测试。
