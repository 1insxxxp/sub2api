# 可用渠道布局对齐设计

## 目标

保留现有模型卡片、计价数据和渠道选择行为，只重构“可用渠道”页面的外层骨架，使顶部筛选、左侧渠道导航和右侧模型内容共享一致的列宽、间距与边界，在桌面、平板和手机端都保持清晰对齐。

## 现状问题

- 筛选栏由 `TablePageLayout` 单独渲染为全宽工具栏，渠道目录内部才建立 `280px + 1fr` 双栏，两层没有共享列轨道。
- 搜索、平台选择、仅有价复选框和刷新按钮依赖自由换行，控件宽度、垂直对齐和换行顺序不稳定。
- 左侧导航、右侧渠道摘要和模型卡片使用不同的圆角、间距和容器起点，视觉边界不连贯。
- 移动端沿用桌面筛选组合，控件容易形成零散行，信息层级不明确。

## 方案选择

采用统一双栏页面骨架：桌面端固定 `260px` 渠道列和弹性模型列；筛选区与内容区使用同一网格。左上角放页面导航摘要，右上角放筛选工具栏；下一行分别放渠道列表和模型内容。

未采用以下方案：

- 全宽筛选栏：改动较小，但依旧无法与右侧模型内容精确对齐。
- 筛选全部移入左栏：会混淆“渠道导航”和“模型过滤”，并加重移动端拥挤。

## 页面结构

### 桌面端（`xl` 及以上）

- 页面主体使用 `260px minmax(0, 1fr)` 两列，列间距统一为 `16px`。
- 左侧顶部为渠道导航标题、渠道数量和简短说明；其下为可滚动渠道列表。
- 右侧顶部为紧凑筛选工具栏；其下依次为当前渠道摘要和模型卡片网格。
- 搜索框占据工具栏剩余宽度；平台选择保持稳定宽度；仅有价使用紧凑开关样式；刷新为 `44px` 方形图标按钮。
- 工具栏、导航栏、渠道摘要共用相同边框、圆角和内边距基线，右侧各模块左边缘完全一致。

### 平板端

- 页面退化为单列，但筛选工具栏使用两行规则网格：搜索占第一行，平台、仅有价和刷新位于第二行。
- 渠道选择继续使用现有移动端选择器，不显示桌面渠道侧栏。

### 手机端

- 搜索框独占一行并保持至少 `44px` 高度。
- 平台选择占剩余宽度，仅有价开关和刷新按钮保持固定触控尺寸。
- 不允许横向滚动；长平台名截断，模型与渠道文本继续允许安全换行。

## 组件边界与数据流

- `AvailableChannelsView.vue` 继续持有搜索、平台、仅有价和刷新状态，并负责 API 请求与过滤。
- 新增可复用的筛选工具栏组件，使用 `v-model`/事件接收现有状态，不发起 API 请求、不计算价格。
- `AvailableChannelCatalog.vue` 负责统一双栏骨架、渠道导航和模型区域；通过具名插槽接收筛选工具栏，从而让筛选区与内部双栏共享列轨道。
- `AvailableChannelModelList.vue`、价格组件和 catalog 构建/计价函数保持不变。

## 状态与异常

- 首次加载、后台刷新、倍率降级、无数据和无搜索结果沿用现有语义。
- 后台刷新时保留旧内容；筛选工具栏仅禁用刷新按钮，不清空筛选条件。
- 没有平台选项时仍显示“全部平台”，控件布局不坍塌。

## 可访问性

- 搜索框、平台选择、仅有价开关保留明确标签。
- 刷新按钮继续提供可访问名称、禁用状态和旋转反馈。
- 所有交互控件至少 `44px` 高；键盘导航和焦点样式保持可见。
- 视觉重排不改变渠道列表的 `listbox/option` 语义或移动端对话框行为。

## 测试策略

- 组件测试覆盖筛选控件的值同步、刷新事件、加载禁用状态和平台列表。
- 目录测试覆盖桌面共享双栏轨道、筛选插槽位置、移动端单列退化及既有渠道选择行为。
- 页面集成测试继续覆盖 API 加载、过滤、刷新保留旧数据、空状态和倍率降级。
- 运行相关 Vitest、ESLint、`vue-tsc --noEmit`、生产构建和 `git diff --check`。
