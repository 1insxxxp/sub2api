# 抽奖开奖记录审计设计

## 目标

让管理员在现有抽奖管理页查看每次抽奖的参与用户、中奖奖品及发放内容。

## 方案

在现有 `/admin/lottery` 页面增加“开奖记录”区域，并提供独立的分页查询接口。后端从 `lottery_draws` 按创建时间倒序读取记录，同时批量读取用户（含已软删除用户）以补充邮箱/用户名；返回奖品快照、余额金额或产品内容、抽奖来源和时间，但不返回幂等 key。

服务层新增管理员查询 DTO 和分页方法，仓储层负责 draws 与 users 的批量查询，管理员 handler 负责解析分页参数并使用标准分页响应。前端 API 使用现有分页响应类型，页面加载配置时同时加载第一页开奖记录，分页或刷新只重新查询记录。

## 错误与兼容性

- 无开奖记录时返回空 `items` 与 `total: 0`。
- 用户已删除时保留 `user_id`，邮箱/用户名显示已删除占位文本。
- 现有用户抽奖历史和抽奖写入流程不变。
- 产品兑换内容只通过管理员接口返回，不扩展公共接口。

## 验证

- 后端服务/仓储测试覆盖分页 DTO 映射、用户信息关联和已删除用户保留。
- 前端 API 测试覆盖管理员记录分页参数。
- 管理页测试覆盖记录加载、用户/奖品字段渲染和翻页触发请求。
