# 系统自定义分组路由卡片与全选设计

## 问题

右侧模型区的每个来源标题都使用 `sticky top-0`。当右侧滚动位置停在来源分段边界，上一分段最后一行会被裁切，而下一分段标题又在列表中出现，视觉上像模型行跑到了标题上方。选择新来源时浏览器滚动锚定还可能保留旧位置，进一步放大错位感。

同时模型路由缺少批量选择能力，来源和模型较多时需要逐条勾选。

## 已确认交互

- 保留左、右两列独立滚动以及右侧同时展示全部已选来源；
- 每个来源改成独立卡片，来源标题处于普通文档流，不再吸顶；
- 右侧模型滚动容器关闭浏览器滚动锚定，避免新增来源时内容自动跳位；
- 顶部来源快捷导航继续滚动定位到对应卡片；
- “模型路由”标题区新增全选复选框，范围是当前已选择来源的全部可见模型；
- 全部已选时为选中，部分已选时为半选，再次点击可全选或取消全选；无可见模型时禁用。

## 状态与边界

全选不新增第二套路由状态，只批量修改现有 `RouteDraft.selected`，并在选中时标记 `draftInitialized`。取消来源后，该来源路由不属于 `visibleRoutes`，不会被全选操作修改；重新选择来源仍恢复原草稿。

## 验证

- 组件测试验证来源标题不再 sticky、每个来源为独立卡片、滚动锚定关闭；
- 组件测试验证全选、半选、取消全选以及只影响当前可见来源；
- 执行相关 Vitest、两套 TypeScript 检查、lint 和生产构建；
- 重新构建本地应用容器并检查健康状态。
