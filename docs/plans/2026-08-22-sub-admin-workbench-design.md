# 二级管理员工作台设计

日期: 2026-08-22

## 背景

当前系统只有 `admin` 和 `user` 两种角色。`admin` 可以访问完整后台，`user` 只能访问用户侧页面。现有“将余额生成兑换码”功能挂在用户兑换页，并通过 `balance_redeem_code_enabled` 用户字段单独放行。

新的需求是增加一个二级管理员角色。这个角色比普通用户多一个单独的“管理员页面”，第一期先迁移“将自己的余额生成兑换码”功能，后续可以在该页面继续增加更多运营工具。

## 目标

- 新增 `sub_admin` 角色，前端显示为“二级管理员”。
- 新增后台侧页面“管理员页面”，推荐路由 `/admin/workbench`。
- `admin` 和 `sub_admin` 都可以访问该页面。
- 普通 `user` 不能访问该页面。
- 现有完整后台页面继续只允许 `admin` 访问。
- 从用户侧 `/redeem` 移除“将余额生成兑换码”入口。
- 余额兑换码生成仍然只扣当前登录用户自己的余额，不允许操作他人余额。

## 推荐方案

采用“轻量角色 + 单页面授权”的方案：

1. 在角色常量中增加 `sub_admin`。
2. 将鉴权概念拆成两层：
   - `isAdmin`: 仅 `admin`，用于完整后台管理权限。
   - `canAccessAdminWorkbench`: `admin` 或 `sub_admin`，用于新“管理员页面”。
3. 后端为工作台创建独立路由组，例如 `/api/v1/admin/workbench/*`，使用新的中间件允许 `admin/sub_admin`。
4. 前端路由增加新的 meta 权限，例如 `requiresAdminWorkbench`，避免把二级管理员误放进其它后台页面。
5. 余额兑换码生成逻辑复用现有服务层扣余额与建码逻辑，但入口从用户兑换页迁移到工作台页面。

这个方案比完整 RBAC 改动小，也比继续使用用户字段开关更清晰。后续如果“管理员页面”内功能变多，可以继续在工作台路由下增加子功能。

## 前端设计

- 新增页面：`AdminWorkbenchView.vue`，标题“管理员页面”。
- 第一块功能区为“余额兑换码”：
  - 显示当前余额。
  - 输入金额、数量、有效期、备注。
  - 生成后显示兑换码列表，支持复制。
  - 展示“我生成的兑换码”列表，沿用分页。
- 用户侧 `/redeem` 只保留兑换码充值与兑换记录。
- 侧边栏：
  - `admin` 仍显示完整后台菜单，并额外可以进入“管理员页面”。
  - `sub_admin` 只显示用户侧菜单和“管理员页面”，不显示完整后台菜单。

## 后端设计

- 新增角色常量 `RoleSubAdmin = "sub_admin"`。
- 创建权限判断函数：
  - `IsAdmin()` 仅判断 `admin`。
  - 新增 `CanAccessAdminWorkbench()` 判断 `admin/sub_admin`。
- 新增或调整中间件，专门保护工作台接口。
- 余额兑换码接口建议迁移到：
  - `POST /api/v1/admin/workbench/redeem/generated`
  - `GET /api/v1/admin/workbench/redeem/generated`
  - `DELETE /api/v1/admin/workbench/redeem/generated/:id`
  - `POST /api/v1/admin/workbench/redeem/generated/batch-delete`
- 生成兑换码时仍使用当前认证用户 ID，扣当前用户余额。
- 普通用户旧的生成接口应关闭或返回 403，防止绕过前端。

## 数据与兼容

- `users.role` 仍使用字符串字段，无需新增表。
- 需要允许 `sub_admin` 作为合法 role。
- 现有用户默认仍为 `user`。
- 原 `balance_redeem_code_enabled` 字段不再作为普通用户生成兑换码权限来源；可以暂时保留字段，避免立刻做破坏性迁移。
- 管理员创建/编辑用户时，角色下拉新增“二级管理员”。

## 错误处理

- 普通用户访问工作台页面或接口：403。
- 二级管理员访问完整后台页面或接口：403，并前端重定向到用户仪表盘或工作台。
- 余额不足：沿用现有余额不足错误。
- 金额、数量、有效期非法：沿用现有校验。

## 测试计划

- 后端服务测试：
  - `sub_admin` 是合法角色。
  - 非法角色仍被拒绝。
  - `sub_admin` 不能访问完整 admin 接口。
  - `sub_admin` 可以访问工作台余额兑换码接口。
  - 普通 `user` 不能访问工作台余额兑换码接口。
  - 生成兑换码扣除当前用户余额。
- 前端测试：
  - 路由守卫允许 `admin/sub_admin` 进入 `/admin/workbench`。
  - 路由守卫拒绝 `user` 进入 `/admin/workbench`。
  - `sub_admin` 看不到完整后台菜单。
  - 用户兑换页不再显示余额转兑换码入口。
- API 客户端测试：
  - 新工作台 API 路径正确。
  - 旧用户侧生成路径不再被 UI 调用。

## 非目标

- 不做完整 RBAC 权限表。
- 不支持二级管理员操作他人余额。
- 不开放二级管理员访问用户管理、分组管理、账号管理、系统设置等完整后台功能。
- 不删除 `balance_redeem_code_enabled` 数据库字段，后续确认无依赖后再单独清理。
