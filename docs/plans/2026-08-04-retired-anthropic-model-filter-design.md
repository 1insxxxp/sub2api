# Anthropic 已退役模型过滤设计

## 背景

部分上游 `/models` 接口仍返回已经无法调用的历史模型。系统当前无条件接受这些模型，并将账号 `model_mapping` 的键聚合到渠道管理候选和用户“可用渠道”列表，导致 `claude-3-5-haiku-20241022` 等已退役模型继续展示。

## 目标

依据 Anthropic 官方生命周期，在直连 Anthropic 账号的上游同步结果、渠道管理候选模型和用户“可用渠道”中隐藏已退役模型。保留已有数据库映射，不执行破坏性清理，也不改变请求计费逻辑。

## 边界

- 仅对 Anthropic 直连账号应用官方退役表。
- Bedrock 等合作平台有独立生命周期，不使用 Anthropic 直连退役表。
- 仅过滤精确的官方模型 ID，不按模糊前缀过滤第三方自定义名称。
- 上游同步返回值会过滤；数据库中已有映射不删除。
- 分组模型聚合时逐账号过滤；若同一模型仍由不受该规则影响的账号提供，则保留展示。

## 实现

增加集中式 Anthropic 模型生命周期判定函数，并在两个数据入口复用：

1. `FetchUpstreamSupportedModels` 返回前按账号类型过滤。
2. `GatewayService.GetAvailableModels` 聚合每个账号映射时按账号类型过滤。

这样渠道管理与用户“可用渠道”共享同一结果，不需要在两个 handler 重复维护规则。

## 测试

- Anthropic 直连账号过滤 `claude-3-5-haiku-20241022`，保留当前有效模型。
- Bedrock 账号即使包含同名模型也不被 Anthropic 直连规则过滤。
- 多账号聚合时，只要不受规则影响的账号仍提供该模型，列表就保留。
- 上游同步结果过滤退役模型。
