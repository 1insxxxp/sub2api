# 充值门槛福利分组设计

## 目标

管理员创建或编辑分组时，可以设置最低累计充值金额。达到门槛的用户可以使用该分组，未达到门槛的用户无法在模型列表中选择、绑定 API Key 或继续使用已经绑定的 API Key。

## 已确认规则

- 使用用户的累计已完成充值金额 `total_recharged` 判断资格。
- 分组门槛为 0 时关闭限制，兼容所有现有分组。
- 余额消耗不影响资格。
- 充值完成后立即生效。
- 退款不回退累计充值资格，沿用签到功能使用的累计充值语义。
- 充值门槛与现有专属分组、手动授权和订阅分组规则叠加。
- 管理员仍可以查看和管理全部分组。

## 数据模型

在 `groups` 表增加 `min_total_recharge_usd`，使用与现有金额字段一致的高精度数值类型，默认值为 `0`。领域层的 `Group` 增加对应字段，创建、更新和返回 DTO 同步支持该字段。

旧分组迁移后门槛为 `0`，无需数据回填。请求中的负数和超过允许精度的金额由服务层拒绝。勾选框只负责控制前端输入状态，最终资格以服务端保存的金额为准。

## 权限判断

分组访问判断集中在服务层的统一资格函数中，输入用户和分组，先判断累计充值门槛，再执行现有订阅、专属分组和公开分组规则。所有入口复用该函数，避免列表显示和实际调用出现差异。

需要覆盖的入口包括用户可用分组与模型列表、API Key 创建、API Key 分组变更、已有 API Key 的请求鉴权，以及模型广场等公开的用户侧分组展示。已有 API Key 在门槛提高后立即失去使用资格，返回结构化的充值门槛错误和中文提示。

## 管理端交互

创建和编辑分组表单增加“充值用户专享”复选框。勾选后显示“最低累计充值金额”输入框，金额必须大于 0。未勾选时保存为 0。分组列表显示简短的门槛标记，避免管理员无法区分受限分组。

## 错误处理

服务端返回稳定错误码，例如 `GROUP_RECHARGE_REQUIRED`，并携带门槛金额和用户累计充值金额等元数据。用户界面显示“累计充值满 $X.XX 后可使用该分组”。余额不足、API Key 过期和分组停用继续使用现有错误处理。

## 一致性与性能

资格判断只读取已加载的用户累计充值金额和分组门槛，不查询订单明细，不创建用户与分组的额外授权记录。充值完成沿用现有 `total_recharged` 更新事务，门槛判断在后续请求中立即读取新值。认证缓存失效时沿用现有用户缓存失效机制，避免旧资格长期驻留。

## 验证范围

- 迁移后旧分组门槛为 0，旧用户行为保持一致。
- 未达到、刚好达到和超过门槛的用户分别验证。
- 门槛开启与关闭、分组编辑、非法金额和多次保存分别验证。
- API Key 创建、换绑、已有 Key 请求和模型列表全部执行同一资格判断。
- 订阅分组、专属分组、公开分组和手动授权组合验证。
- 充值完成后无需重新配置即可使用，余额消耗不影响资格。
- 中文错误提示、错误码、移动端表单和深色模式验证。
