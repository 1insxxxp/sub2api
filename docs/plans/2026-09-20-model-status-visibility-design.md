# 模型监控展示范围设计

## 目标

为每个公开分组增加独立的“模型监控展示范围”配置。关闭限制时默认展示该分组全部模型；开启限制后，仅在模型状态页隐藏未选中的模型，实际模型调用、模型列表和现有模型白名单保持原有行为。

## 约束与语义

- 现有 `groups.model_allowlist` 继续负责实际模型准入，不复用、不改变其语义。
- 新配置是分组级统一配置，对看到该分组模型状态的用户生效，不按单个用户拆分。
- 配置为空或关闭时等价于全部展示，兼容已有分组数据。
- 模型监控接口在服务端过滤，避免把隐藏模型及其统计数据发给客户端；分组统计和全局汇总在过滤后重新计算。
- 只过滤模型状态展示数据，不改变网关、模型目录、计费、路由或权限判断。

## 数据与接口

在 `groups` 表增加 JSONB 字段，例如 `model_status_visibility`，默认 `{}`。服务层使用独立结构表示 `enabled` 与 `models`，对名称做 trim、大小写不敏感去重，并沿用现有候选模型精确 ID；不支持把现有实际调用白名单的通配规则带入展示配置，避免产生意外的目录语义。

管理员分组 DTO 的创建、读取、更新接口读写该字段。模型状态服务构建完整缓存报告后，在返回前按每个分组的展示配置过滤模型，并重新合并该分组和 summary 指标。缓存仍保存完整报告，配置变更不需要重新聚合统计。

## 管理端体验

在管理员“分组 → 新建/编辑”表单中，在现有“模型白名单”附近增加独立的“模型监控展示范围”区块：开关默认关闭，说明“关闭时展示全部模型，不影响实际请求”；开启后复用候选模型加载、全选、清空、自定义条目和移动端可滚动列表，但保存字段独立于模型白名单。界面明确区分“监控展示”与“实际调用限制”。

## 错误与兼容

- 历史分组没有字段时按关闭处理。
- 配置启用但模型列表为空时按无模型展示并在管理端阻止保存，避免误隐藏全部模型；关闭开关可恢复全部展示。
- 候选模型加载失败时保留已保存条目并显示错误，不覆盖现有配置。
- 服务端不把上游地址、账号或隐藏模型统计泄露到响应。

## 测试

- 迁移/DTO：默认值、读写和旧分组兼容。
- 服务：关闭时保留全部；启用时过滤模型、重算分组和 summary；不影响实际模型白名单逻辑。
- 管理端：独立字段绑定、启用/关闭、保存与移动端列表动作。
- 前端模型状态：隐藏模型不渲染，剩余模型和汇总数据正确。
