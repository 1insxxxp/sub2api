# 分组工具栏创建入口响应式修复设计

## 问题

分组管理工具栏在加入“新建系统自定义分组”后，同时包含筛选控件、刷新、列设置、排序以及两个创建入口。工具栏仍在 `lg` 断点切换为单行，但桌面端还要扣除侧边栏宽度，导致实际内容宽度不足时右侧创建按钮可能被挤出可视区域。

## 方案

- 普通桌面宽度下保持两行：筛选区一行，操作区一行并右对齐。
- 仅在 `2xl` 超宽屏下恢复筛选区与操作区同一行。
- 将两个创建入口组织为独立的创建动作组，保持相邻、右对齐和不换行的按钮文字。
- 刷新、列设置和排序仍属于次要动作组，功能与顺序不变。
- 不修改分组接口、弹窗状态或权限逻辑。

## 验证

- 组件测试确认工具栏使用普通桌面两行、超宽屏单行的响应式契约。
- 组件测试确认创建动作组同时包含系统自定义分组和普通分组两个入口。
- 运行 GroupsView 相关测试、TypeScript 类型检查、ESLint 和生产构建。
