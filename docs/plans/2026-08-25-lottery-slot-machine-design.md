# 抽奖老虎机动画设计

## 目标

将用户端抽奖区域从静态奖品卡片和普通按钮，升级为参考图风格的三列老虎机滚轴动画，同时保持现有服务端抽奖规则、奖品权重、余额入账、兑换码发放和历史记录不变。

## 已确认范围

- 抽奖动画采用三列老虎机滚轴，不改成转盘或翻牌。
- 前端动画只负责视觉反馈，中奖结果始终以服务端 `POST /lottery/draw` 返回值为准。
- 三列滚轴展示当前活动的奖品名称和类型图标；奖品数量不足三项时循环填充展示。
- 点击抽奖后锁定按钮和滚轴，滚动约 1.8 秒并逐列减速，最终停在服务端返回的奖品。
- 抽奖成功后沿用现有结果弹窗；产品内容继续支持复制，历史记录继续刷新。
- 未配置活动、活动关闭、次数用尽、奖品为空和请求失败时，页面仍使用现有提示逻辑，不启动动画。
- 移动端保持三列布局，降低列宽与字号但不改变核心操作；支持 `prefers-reduced-motion`，减少动态效果。

## 方案选择

### 方案 A：CSS 三列老虎机滚轴（采用）

使用 Vue 状态控制每列当前奖品和动画阶段，CSS `transform`/`transition` 完成滚动和减速。动画结束后将服务端中奖奖品放入高亮中心位。实现依赖少、视觉贴合参考图、移动端容易适配。

### 方案 B：Canvas 或第三方动画组件

可以获得更复杂的粒子和滚轴效果，但会增加打包体积、测试难度和无障碍处理成本，与现有页面的轻量交互不匹配。

### 方案 C：纯 CSS 无限滚动

视觉实现简单，但难以稳定地让三列在服务端结果对应的位置停下，容易出现用户看到的奖品和实际中奖奖品不一致，因此不采用。

## 交互与状态

### 空闲状态

- 显示三列奖品预览，每列中心位置带浅色高亮。
- 主按钮显示“开始抽奖”，剩余次数沿用现有活动状态。
- 奖品列表仍可在老虎机下方保留为简要说明，避免用户看不懂奖品内容；不再把静态奖品卡片作为主要抽奖入口。

### 抽奖中

- 生成已有的 `attempt_key` 并立即调用服务端抽奖接口。
- 在请求期间开始滚动动画，按钮不可重复点击。
- 三列使用不同延迟结束，形成由左至右的减速停靠效果。
- 如果接口失败，停止动画并恢复上一次展示，不弹出虚假的中奖结果。

### 成功状态

- 将服务端返回奖品设置为三列中心高亮项。
- 显示现有中奖结果弹窗，余额奖品展示到账金额，产品奖品展示交付内容。
- 刷新状态和第一页历史记录，保证剩余次数和历史与服务端一致。

## 文件与组件边界

- 修改 `frontend/src/views/user/LotteryView.vue`：增加老虎机结构、动画状态、抽奖中状态和结果同步。
- 如模板复杂度明显增加，新增 `frontend/src/components/lottery/LotterySlotMachine.vue`，由用户页面传入奖品和抽奖回调；当前优先在页面内实现，避免过早抽象。
- 继续使用 `frontend/src/api/lottery.ts` 的现有接口，不新增后端字段或接口。
- 修改 `frontend/src/i18n/locales/zh/lottery.ts` 与 `frontend/src/i18n/locales/en/lottery.ts`，补充老虎机区域文案、动画中状态和无障碍标签。

## 无障碍与响应式

- 抽奖按钮使用真实 `button`，动画期间设置 `aria-busy` 和禁用状态。
- 滚轴容器使用 `aria-live="polite"` 在成功后播报中奖结果，不在快速滚动过程中持续播报。
- `prefers-reduced-motion: reduce` 下跳过快速滚动，保留短暂淡入和结果高亮。
- 桌面端使用较宽滚轴卡片，手机端通过 `grid-template-columns: repeat(3, minmax(0, 1fr))` 缩小卡片；奖品名称使用截断或换行，不能撑破页面。

## 测试策略

- 先增加页面行为测试，覆盖空闲状态、抽奖中按钮禁用、服务端中奖结果成为中心项、请求失败恢复和减少动态模式。
- 运行相关 Vitest 测试确认测试先失败，再实现状态机和组件交互。
- 运行 TypeScript、Lint 和生产构建，确认 CSS 动画和模板类型没有回归。
- 保留现有抽奖 API 测试与页面错误映射测试。

## 验收标准

- 用户看到的是参考图风格的三列老虎机，而不是普通静态按钮。
- 点击一次只产生一次服务端抽奖请求，动画结束后显示的奖品与接口返回一致。
- 余额、产品内容、剩余次数和历史记录行为与现有版本一致。
- 活动不可用时页面不显示可操作的老虎机按钮。
- 桌面端和手机端均不溢出，减少动态模式下仍能完成抽奖。
