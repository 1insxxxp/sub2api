# 本地页面接口性能优化设计

## 目标

降低后台列表、用量记录、仪表盘等页面的首次加载时间，优先确认数据库执行计划是否因生产数据复制后的统计信息失真而变慢；所有验证先在本地复制库进行，不改变线上服务和业务数据。

## 方案

第一阶段只做可逆的数据库观测与统计优化：记录代表性接口耗时，查看 PostgreSQL 当前执行计划，对大表执行 `ANALYZE`，再次记录耗时和计划变化。重点关注 `usage_logs`、`usage_billing_dedup`、`usage_response_outcomes` 以及用户、账号、分组列表涉及的分页、排序、时间筛选和总数查询。

第二阶段根据第一阶段证据补充缺失的组合索引，并用同一批查询做前后对比。索引只通过迁移文件加入，避免直接修改线上结构。

第三阶段再考虑接口和前端行为优化：将非关键统计延后或短时缓存，合并重复请求，延迟非首屏请求，并对长列表使用增量或虚拟渲染。只有在数据库优化不能达到目标时才进入这一阶段。

## 数据流与约束

本地后端继续使用 `/Volumes/Sub2LocalData/runtime/data`、PostgreSQL `127.0.0.1:55429` 和 Redis `127.0.0.1:56331`。测试使用现有 `dev` 分支和 launchd 本地服务，不重建或清空数据库，不接触生产服务器。

## 验证

记录代表性接口的 P50/P95 响应时间、数据库执行计划和扫描行数；执行 `ANALYZE` 后重复同一批查询。若需要代码改动，再补对应后端测试、前端测试和构建检查。
