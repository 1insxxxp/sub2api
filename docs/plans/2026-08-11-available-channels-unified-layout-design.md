# 可用渠道统一布局设计

## 目标

把当前由“导航标题卡片、导航列表卡片、筛选卡片、渠道信息卡片”拼接而成的页面，重构为两个明确层级：左侧渠道目录与右侧模型内容。保持现有模型卡片、价格、倍率、筛选数据和渠道选择逻辑不变。

## 桌面布局

- 页面使用约 `240px + minmax(0, 1fr)` 的双栏网格。
- 左侧是一块连续的轻量渠道目录，标题、总数和渠道列表共用一个容器，不再嵌套两张卡片。
- 当前渠道以主色细边、浅色底和加粗名称表示；其他渠道使用低干扰的列表行。
- 每个渠道统一为名称、平台、分组/模型统计两行信息，长名称允许换行。
- 左侧目录保持 sticky 和独立滚动，但边框、阴影和内边距只出现一次。

## 右侧内容

- 当前渠道信息与筛选控件合并为一个统一顶部面板。
- 顶部第一行展示渠道名称、描述、平台和分组/模型统计。
- 顶部第二行展示搜索、平台筛选、仅看有价和刷新按钮。
- 搜索框占据剩余宽度；平台筛选宽度稳定；开关和刷新按钮保持 44px 触控高度。
- 删除原有独立渠道信息卡片，模型列表紧接统一顶部面板。

## 响应式

- `xl` 以下隐藏桌面渠道目录，继续使用现有移动端渠道选择弹窗。
- 平板端工具栏优先保持一行；窄屏把搜索独占首行，其他筛选排列在第二行。
- 320px 宽度下不出现横向滚动，控件文案可压缩但保留完整无障碍标签。

## 状态与行为

- 首屏加载、刷新保留旧内容、倍率降级警告、无数据和无搜索结果语义保持不变。
- 无结果时仍保留工具栏，用户可以清空筛选。
- 当前渠道被刷新移除时，继续回退到第一个可用渠道。
- 不新增 API，不修改价格、倍率、计费或模型聚合逻辑。

## 验证

- 组件测试覆盖单一左栏容器、统一顶部面板、控件顺序、空态和响应式类。
- 页面集成测试覆盖搜索、平台、仅有价、刷新、渠道回退及移动端选择。
- 运行相关 Vitest、完整前端类型检查、ESLint 和生产构建。
- 在 1440px、768px、390px、320px 四种视口进行真实页面视觉检查，并验证无横向溢出。
