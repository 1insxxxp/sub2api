# 运维上游错误分组定位视图设计

## 背景

现有运维面板的“上游错误明细”以分页表格展示单条错误记录。排查一段时间内的上游故障时，需要逐行打开详情，才能判断哪些分组、模型和账号集中报错，定位效率较低。列表接口也只返回基础字段，不能依赖当前页数据完成完整聚合。

## 目标

- 在“上游错误明细”弹窗增加“分组定位”入口。
- 使用当前时间范围、平台、分组、关键词、状态码、阶段、错误归属和视图模式筛选条件。
- 服务端一次聚合返回完整的分组树，按错误数量降序排列：分组 → 模型 → 上游账号 → 错误原因。
- 第一屏直接显示每个分组的错误总数、涉及模型数和账号数；展开后能快速看到模型、账号、错误次数、最近时间、状态码和原因摘要。
- 点击聚合节点可以回到现有错误详情，查看脱敏后的正文和重试链路。
- 桌面端和移动端都保持可读，长账号名、模型名和错误原因可以换行。

## 非目标

- 不改变现有错误列表、详情接口和错误记录保存逻辑。
- 不在聚合视图中展示未脱敏的上游密钥、请求体或原始地址。
- 不把聚合视图做成新的独立运维页面。

## 交互与界面

在 `OpsErrorDetailsModal` 的筛选工具栏增加“分组定位”按钮，仅在 `errorType=upstream` 时显示。点击后打开宽屏 `BaseDialog`。

弹窗顶部保留当前时间范围和筛选摘要，并提供刷新和关闭操作。主体采用逐级可折叠的中性材质卡片：

1. 分组行：分组名称、错误总数、模型数、账号数、最近错误时间。
2. 模型行：模型名称、错误次数、状态码分布、最近错误时间。
3. 账号行：账号名称/编号、错误次数、最近错误时间、最近状态码、原因摘要。
4. 原因行：显示脱敏后的原因摘要和次数；点击账号或原因打开现有 `OpsErrorDetailModal`。

分组默认展开，模型和账号按错误次数降序，数量相同按最近时间降序。移动端改为单列卡片和可折叠层级，内容使用断词和换行避免横向溢出。

## 后端接口与数据

新增管理员接口 `GET /admin/ops/upstream-errors/summary`，复用现有错误筛选参数，并支持可选的 `group_by` 预留字段。当前固定返回分组、模型、账号、原因四级结构。返回字段包含：

- 分组：`group_id`、`group_name`、`error_count`、`model_count`、`account_count`、`latest_at`。
- 模型：`model`、`error_count`、`latest_at`、状态码计数。
- 账号：`account_id`、`account_name`、`error_count`、`latest_at`、最近状态码、原因摘要列表。
- 原因：脱敏后的 `message`、`error_type`、`status_code`、`count`、最近时间，以及一个可跳转的代表错误 ID。

聚合查询直接在数据库执行，按现有错误日志筛选逻辑限定范围，并只纳入上游错误视图的记录。原因文本使用已存储的脱敏、截断字段；接口不重新读取或返回原始请求内容。

## 错误处理与性能

- 筛选无数据时返回空分组数组和零计数，弹窗显示空状态。
- 接口失败时保留弹窗和筛选条件，显示可重试提示，不影响原错误列表。
- 聚合结果限制单个分组的模型、账号和原因明细数量，并返回截断标记，避免异常数据撑大响应；总数仍准确。
- 对时间、分组、平台、模型和状态字段复用现有索引与参数校验。

## 验证

- 后端：筛选条件、分组计数、排序、空结果、敏感字段脱敏的单元测试和仓储查询测试。
- 前端：按钮入口、参数传递、分组展开/收起、跳转详情、加载/错误/空状态、移动端换行的组件测试。
- 运行现有运维错误详情测试、相关后端测试和前端生产构建。
