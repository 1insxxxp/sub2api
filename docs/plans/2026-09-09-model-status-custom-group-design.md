# 模型状态页联动自定义分组设计

## 背景

模型状态页当前只能按公开分组查看模型。用户已经可以在“自定义分组”中维护一组真实来源模型，希望这组配置也能作为模型状态页的查看预设。

## 目标

- 登录用户可以在模型状态页选择自己的自定义分组。
- 选择后只展示该分组中配置的真实来源模型及其状态数据。
- 保留现有公开分组筛选、自动刷新、移动端选择器和未登录访问能力。
- 不改变模型状态公开接口，不让用户配置影响服务端统计范围。

## 非目标

- 不在模型状态页新增独立的逐模型编辑器。
- 不把自定义分组的 `public_model` 别名当作模型状态名称。
- 不修改自定义分组的路由、计费或 API Key 绑定行为。

## 方案

在现有分组选择器中增加用户自定义分组选项。登录后并行加载模型状态报告和自定义分组列表；未登录时只加载模型状态报告。

自定义分组筛选使用每个模型的真实来源标识匹配状态报告：

```text
custom_group_model.source_group_id === model_status_group.id
custom_group_model.source_model === model_status_model.name
```

筛选结果仍按状态报告中的公开分组渲染，因此同名模型在不同来源分组中不会被合并，状态卡片和时间段明细继续使用原始数据。

## 交互规则

- 默认选中“全部公开分组”。
- 选择自定义分组后，筛选器保留该选择，并显示匹配到的模型数量。
- 自定义分组没有匹配模型时，显示现有空结果状态，不隐藏刷新和返回操作。
- 自定义分组加载失败不阻断模型状态页；筛选器退回公开分组，并保留模型状态报告。
- 自定义分组被删除、禁用或来源模型失效后，刷新模型状态页时自动回退到“全部公开分组”。
- 当前选择继续使用现有 `localStorage` 持久化，但使用独立前缀区分公开分组 ID 和自定义分组 ID。

## 数据与实现边界

- 使用已有 `customGroupsAPI.list()`，只展示 `status === 'active'` 的用户自定义分组。
- 不向 `/model-status` 增加查询参数，也不改后端缓存和聚合逻辑。
- 自定义分组选项值采用前缀格式，例如 `custom:12`，避免和公开分组数字 ID 冲突。
- 过滤后的分组对象保留原始模型卡片引用和时间段数据，避免复制或重算指标。
- 语言包补充自定义分组选项、加载失败和无匹配提示。

## 测试

- 未登录时不请求自定义分组，公开分组筛选行为保持不变。
- 登录且存在自定义分组时，筛选器显示自定义分组并按来源分组/模型过滤。
- 同名模型来自不同公开分组时，只保留自定义分组明确配置的来源项。
- 自定义分组无匹配项、接口失败、分组失效时页面仍可正常刷新并回退。
- 验证桌面和移动端选择器显示，回归模型状态原有状态卡片、倒计时和明细测试。
