# 可用渠道模型广场风格 UI 设计

## 目标

参考 QuantumNous/new-api 模型广场的视觉语言，重构现有“可用渠道”页面的展示层。只改变 UI 结构、信息层级和交互表现，不改变渠道 API、用户可见范围、分组倍率、官方价/本站价计算或计费逻辑。

## 设计方向

采用紧凑模型列表：以模型为视觉焦点，同时保留渠道和分组上下文。顶部提供搜索与筛选，列表行突出模型名、平台、本站价和官方价；展开后查看提供渠道、分组及完整价格维度。

## 页面结构

- 顶部工具栏：模型/渠道搜索、平台筛选、仅有价筛选、刷新状态。
- 桌面端：紧凑列表，列出模型、平台/能力、本站价、官方价、可用渠道/分组数量。
- 行展开：显示渠道与分组徽章、输入/输出/缓存/图片/请求等价格明细，以及未定价说明。
- 移动端：单列卡片，价格信息始终可见；平台和渠道筛选通过底部弹窗完成，不产生横向滚动。
- 保留首屏加载、刷新中保留旧内容、无数据、无筛选结果、倍率降级和未定价状态。

## 交互与无障碍

- 列表行可用键盘展开，使用明确的 `aria-expanded`/`aria-controls`。
- 折叠状态仅由用户操作控制；刷新和排序不意外丢失用户选择。
- 移动筛选弹窗支持 Escape、遮罩、关闭按钮、焦点保存/恢复和 body 滚动锁定。
- 使用现有中英文 i18n；颜色同时配合文字和标签，不依赖颜色单独传达状态。

## 约束

- 不新增后端接口或数据库字段。
- 不复制 new-api 源码，仅借鉴公开 UI 交互和信息布局；如保留来源说明，沿用项目现有合规页面。
- 价格继续由现有 catalog 统一计算，页面组件不重复计算金额。

## 验收

- 桌面端模型名、本站价、官方价无需展开即可看见。
- 不同渠道/分组提供的同名模型不会合并成错误价格。
- 移动端在窄屏下可完成搜索、筛选、展开和查看价格。
- 相关组件测试、类型检查、lint 和构建全部通过。
