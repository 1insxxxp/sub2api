# 一键测试账号全部模型设计

## 目标

在管理员账号测试弹窗中新增“一键测试全部模型”，沿用当前测试模式和提示词，依次测试当前账号的所有可用模型，并清晰展示每个模型的成功或失败结果。现有单模型测试行为保持不变。

## 方案

采用前端串行调度，复用现有 `POST /api/v1/admin/accounts/:id/test` SSE 接口。弹窗打开时已有模型列表加载逻辑；批量测试直接使用当前模式下可测试的模型选项，逐个提交与单模型测试相同的请求体。每个请求完成后再开始下一个，避免同时占用账号并发和触发上游限流。

批量测试只在当前模式具有模型选择时显示。Grok 的搜索、TTS、STT、实时模式属于独立端点，没有按模型选择，因此不提供批量按钮。Grok 的文本、图像和视频模式以及其他平台沿用各自现有测试路径。

## 数据流与状态

- 批量开始时保存本次模型快照、清空旧结果并创建 `pending` 状态。
- 当前模型显示 `testing`，读取 SSE 中的 `test_complete` 或 `error` 事件；只有 `test_complete.success === true` 才计为成功。
- HTTP 错误、读取流失败、解析失败和 `error` 事件均计为失败，并保存可展示的错误摘要。
- 当前请求使用独立 `AbortController`。用户停止或关闭弹窗时取消请求，当前结果保留，未开始项目标记为取消。
- 批量汇总显示总数、成功数、失败数和取消数；全部完成后不覆盖单模型测试的输出区能力。

## 界面

在现有开始测试按钮旁增加“测试全部模型”操作。批量运行时单模型和批量按钮均禁用，停止按钮可取消批量。结果区按模型列出状态、耗时和失败信息，使用现有颜色和图标体系，并补充中英文国际化文案。

## 错误处理与兼容性

批量请求沿用单模型请求头、认证和请求体构造逻辑，不新增后端路由或数据库字段。单模型测试函数保持原调用路径；批量调度只负责遍历和汇总，因此平台特殊模式、媒体请求和现有 SSE 解析继续由原逻辑处理。批量过程中某个模型失败不会阻止后续模型继续测试。

## 测试

- Vue 组件测试：验证批量按钮按模型模式显示、按顺序发送请求、混合成功失败汇总、失败继续后续模型、停止时取消未开始项。
- 保留并运行现有单模型测试，确保请求体、图片预览和 Grok 默认模型行为不变。
- 运行相关前端测试与格式检查。
