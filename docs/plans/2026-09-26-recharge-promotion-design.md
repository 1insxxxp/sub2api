# 充值活动优惠设计

## 目标

增加一个全站充值活动配置：在指定时间窗口内，符合资格的用户使用活动倍率获得额外到账余额；管理员可以维护用户黑名单，黑名单用户继续使用正常充值规则。

## 方案

采用现有 settings KV 保存一份活动 JSON，而不是新增活动表。当前需求只有一个全站活动，KV 可以保持配置原子更新，避免新增迁移、活动列表和重叠活动冲突处理。后台继续放在支付设置页，与正常充值倍率和快捷充值金额放在同一配置上下文中。

活动配置包含：

- `enabled`：是否启用活动；
- `name`：活动展示名称，可为空；
- `start_at`、`end_at`：RFC3339 时间，按服务端 UTC 保存，区间为 `[start_at, end_at)`；
- `multiplier`：活动期间的最终充值倍率，必须大于 0；
- `blacklist_user_ids`：不享受活动的用户 ID 列表，去重且只接受正整数。

活动倍率直接替换正常全局/档位倍率。活动只改变订单的到账余额 `amount`，不改变用户支付金额 `pay_amount`、手续费、支付渠道选择或金额校验。活动产生的到账余额沿用现有充值流水语义，继续参与充值排行、返利和充值门槛统计。

## 数据流

1. 管理员读取支付设置时，返回完整活动配置，包含黑名单 ID，供管理界面编辑。
2. 管理员保存支付设置时，后端校验时间格式、开始时间早于结束时间、倍率和用户 ID，并将 JSON 作为单个 setting 写入。
3. 用户打开充值页时，`checkout-info` 根据当前认证用户、服务端时间窗口和黑名单计算有效规则，只返回活动是否生效、展示名称/结束时间和有效倍率，不返回黑名单内容。
4. 用户创建余额订单时，服务端在加载用户后再次计算资格。符合条件时使用活动倍率，否则使用原有档位/全局倍率。订单写入的 `amount` 仍是最终到账余额，因此支付完成和重试流程无需改变。

## 管理端交互

支付设置页新增“充值活动”分区，包含启用开关、名称、开始/结束时间、活动倍率和黑名单用户选择器。用户选择器复用现有的搜索、按邮箱/ID 添加、标签删除和已删除用户标识能力；只显示黑名单数量和已选用户，不改变用户管理页。

## 用户端交互

充值页在当前活动生效时显示活动名称、倍率和结束时间，充值预览使用后端返回的活动有效倍率。黑名单用户只看到正常充值规则，不显示被排除原因或其他用户名单。

## 校验与兼容

- 未配置活动、活动关闭、时间不在窗口内、活动配置非法或用户在黑名单时，完全回退现有充值倍率和快捷金额行为。
- 活动配置读取失败时不得阻断普通充值配置读取；后端采用安全默认值关闭活动。
- 不新增数据库表或迁移；旧版本配置没有活动 JSON 时保持原行为。

## 测试范围

- 后端活动 JSON 解析、字段校验、时间边界、黑名单命中和倍率替换测试。
- 后端下单测试确认支付金额不变、订单到账金额使用活动倍率，黑名单回退正常倍率。
- `checkout-info` 测试确认只返回当前用户有效活动信息，不泄露名单。
- 管理设置前端测试覆盖读取、编辑和提交活动字段。
- 用户充值页测试覆盖活动预览、结束时间和黑名单用户回退。
