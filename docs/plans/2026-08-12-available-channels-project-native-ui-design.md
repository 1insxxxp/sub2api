# 可用渠道项目原生 UI 优化设计

## 背景

当前“可用渠道”已经具备渠道导航、模型卡片、官方价与本站价对比、价格区间和渠道方案详情，但视觉层级仍存在以下问题：

- 左侧渠道导航与右侧工具栏像两套独立卡片，顶部、边界和内容基线不够统一。
- 工具栏控件尺寸虽接近，但搜索、平台筛选和刷新按钮的焦点与交互反馈不完整。
- 模型卡片使用彩色渐变顶边、悬浮位移和多层价格容器，与项目后台现有的克制白底卡片风格不一致。
- “展开方案”占据整行且语义不够明确；展开后的方案继续嵌套大卡片，信息层级过重。
- 大量模型同时显示时缺少浏览器渲染优化。

本轮只调整展示层和交互层，不改变渠道 API、模型可见范围、官方价/本站价计算、分组倍率、实际倍率或真实扣费逻辑。

## 视觉方向

采用“项目原生的精致紧凑风”：保留现有蓝色主品牌、白底细边框和轻阴影，将绿色仅用于价格与节省金额的语义强调。避免彩色渐变、大幅悬浮位移和层层套卡。

## 桌面布局

- 保留 `240px + minmax(0, 1fr)` 左右布局。
- 左侧导航和右侧内容使用相同的顶部起点、圆角、边框颜色与间距节奏。
- 左侧渠道项采用紧凑垂直列表；平台标签、分组数和模型数对齐显示。
- 当前渠道使用浅蓝背景、主色边框和左侧细指示条；悬停与键盘焦点提高对比度。
- 左侧导航跟随页面滚动保持可见，但不使用固定 `640px` 高度截断内容。

## 右侧头部与筛选

- 渠道名称、描述、平台标签和数量统计构成同一张头部卡片的第一行。
- 搜索、平台筛选和刷新按钮位于第二行，统一为 44px 高并使用相同边框、圆角和焦点环。
- 搜索框补充可访问名称、字段名称和关闭自动填充。
- 刷新状态继续保留旧数据，并以不阻塞内容的状态提示展示。

## 模型卡片

- 保留响应式一列、两列、三列模型网格。
- 移除渐变顶边和悬浮上移，改为稳定的白底、细边框与项目标准阴影。
- 品牌图标、模型名和平台标签形成紧凑头部。
- 价格主体使用轻量单层容器：本站价为主信息，官方价和优惠比例紧邻展示。
- 输入、输出、缓存等维度使用固定三列对齐：名称、官方价、本站价。
- 金额继续使用等宽数字和现有价格格式化逻辑。
- 卡片增加 `content-visibility: auto` 与保守的固有尺寸提示，降低长列表初次渲染开销。

## 渠道方案详情

- 操作文案改为“查看渠道方案（N）”与“收起渠道方案”。
- 操作区改为轻量页脚按钮，并显示方向箭头，不再使用高权重整行强调。
- 展开区域使用紧凑方案行：渠道名、分组名、平台、分组倍率、实际倍率与价格维度在同一信息结构中展示。
- 桌面端按列对齐，移动端自动堆叠；避免在卡片内继续嵌套大型卡片和多层阴影。

## 移动端

- 保持底部渠道选择器和单列模型卡片。
- 触发器、搜索框、关闭按钮和渠道选项均提供 44px 触摸区域、明确悬停/焦点状态和安全区处理。
- 长渠道名、模型名、价格和分组名均允许安全换行，不产生横向滚动。

## 可访问性与规范

- 搜索输入提供 `aria-label`、`name`、`autocomplete="off"`。
- 原生按钮保留清晰的 `focus-visible` 状态；装饰图标不进入辅助技术名称。
- 动画仅使用颜色、阴影和透明度，并尊重 `prefers-reduced-motion`。
- 数字比较使用 `tabular-nums`。
- 加载、刷新、无结果与无定价状态保持明确。

## 验证范围

- 组件测试覆盖桌面左右结构、工具栏可访问属性、渠道导航交互、模型卡片价格层级、方案文案和详情结构。
- 运行相关 Vitest、ESLint、Vue TypeScript 检查和生产构建。
- 在本地热更新环境分别验证桌面宽度和 320px/390px 移动宽度，无横向溢出。
