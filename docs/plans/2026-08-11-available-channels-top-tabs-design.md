# 可用渠道顶部标签布局设计

## 目标

移除桌面端高而窄的左侧渠道导航卡片，将渠道选择改为页面顶部的横向标签栏，让搜索工具栏和模型卡片网格获得完整页面宽度。模型、价格、渠道过滤和数据请求逻辑保持不变。

## 页面结构

桌面端页面改为单列结构：渠道标签栏、当前渠道与筛选工具栏、模型卡片网格依次向下排列。原先 `240px + 1fr` 的双栏网格和左侧 `aside` 完全移除。

顶部渠道标签栏使用一行横向滚动容器。每个标签紧凑显示渠道名、平台标识以及分组/模型数量；当前渠道使用主色背景、边框和底部强调线，不再使用大卡片套小卡片。标签过多或名称过长时只在标签栏内部横向滚动，不产生页面级横向滚动。

平板与手机继续使用现有渠道选择器，避免窄屏标签过度拥挤。切换渠道后，当前选择、模型投影和空状态行为保持一致。

## 交互与可访问性

桌面标签栏保留 `listbox/option` 语义、`aria-selected`、焦点环和详情区域关联。键盘导航从适合纵向列表的上下方向键调整为适合横向标签的左右方向键，同时继续支持 Home、End。通过键盘切换时，焦点跟随选中标签。

## 加载与空状态

首次加载骨架改为顶部横向标签骨架加全宽详情骨架。无数据时保留顶部导航摘要和全宽空状态。刷新提示、倍率降级提示和移动端选择器继续沿用现有逻辑。

## 模型网格

模型卡片继续使用现有单列、双列和三列响应式断点，不修改价格卡片内部结构。移除左栏后，网格自然获得更宽的卡片空间，模型名、价格表和展开方案不再被侧栏挤压。

## 测试

- 桌面端不再渲染左侧 `aside`，而是渲染顶部横向标签栏。
- 标签栏支持点击、左右方向键、Home 和 End 切换。
- 标签栏具备内部横向滚动和紧凑标签样式。
- 工具栏、详情和模型网格均为全宽单列流。
- 移动端渠道选择器、空状态、刷新状态和现有模型投影测试继续通过。
- 运行相关 Vitest、ESLint、类型检查、生产构建与完整前端测试。
