# 系统自定义分组独立滚动设计

## 问题

系统自定义分组弹窗当前由 `BaseDialog` 的整个 body 承担纵向滚动。来源栏本身没有滚动容器，模型栏虽然有最大高度和内部滚动，但第一个来源的模型较多时会占满可视区域，后续已选来源只能在下方继续滚动。结果是：

- 滚动来源列表时，右侧模型区和整个表单一起移动；
- 勾选多个来源后，管理员容易误以为右侧只展示了第一个来源。

## 已确认交互

桌面端采用“独立滚动 + 多来源全部分段展示”：

- 来源栏和模型栏共享固定的工作区高度，但各自拥有独立的滚动容器；
- 两个滚动容器使用 overscroll containment，滚到边界时不把滚动继续传递给弹窗 body；
- 右侧按来源标题分段渲染全部已勾选来源，不改成单来源切换；
- 右侧顶部显示全部已选来源的快捷导航，点击后定位到对应来源段；
- 来源段标题在右侧滚动容器内吸顶，方便确认当前编辑来源；
- 手机和平板窄屏保持上下排列和页面自然滚动，避免嵌套小滚动区。

## 状态与数据

继续以 `selectedSourceIDs` 作为来源选择的唯一状态，以 `selectedCandidates` 过滤出所有已选来源。右侧导航和来源分段都从同一个 `selectedCandidates` 派生，因此不会出现导航、可见模型和保存快照三套状态不一致。

现有 `RouteDraft`、别名、启用状态和保存快照语义不变。取消来源仍只从有效快照中排除该来源，重新勾选时恢复草稿。

## 可访问性与测试

- 快捷导航使用普通按钮，并包含来源名称；
- 来源段提供稳定 test id 和 source id，便于验证多来源同时存在；
- 测试必须先复现：两个来源勾选后右侧出现两个来源段，左右滚动容器具有独立滚动和防串联样式；
- 再验证定位按钮只滚动右侧模型容器，不改变来源选择和路由草稿；
- 保留现有创建、编辑、同步、冲突和删除回归测试。
