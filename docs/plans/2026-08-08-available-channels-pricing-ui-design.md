# 可用渠道价格目录 UI 重构设计

## 背景

当前“可用渠道”页面以五列表格承载渠道、描述、平台、分组和模型。模型数量较多时，支持模型列会堆叠大量标签；模型价格只在悬浮或聚焦标签后出现，桌面端需要 hover，移动端需要点击，用户无法快速比较官方价与本站实际价。

本次重构将页面改造成响应式价格目录：桌面端使用“渠道导航 + 价格详情”双栏结构，移动端使用渠道选择抽屉和全宽价格卡。模型价格固定可见，同名模型按来源分组分别展示，确保倍率和计费来源清晰。

## 目标

- 用户进入页面后无需悬浮或点击即可看到官方价和本站价。
- 同一模型位于不同分组时分别展示，不以“最低价起”合并。
- 保留渠道、平台、分组、专属授权、倍率和高峰规则等来源信息。
- Token、按次、生图和阶梯计费使用适合自身量纲的展示方式。
- 桌面端快速切换渠道，移动端不出现横向滚动或 hover 依赖。
- 价格计算集中在统一视图模型中，桌面端和移动端共享同一数据口径。
- 保持现有 API 和计费逻辑不变，降低发布与回滚风险。

## 非目标

- 不修改网关路由、模型调度或实际扣费逻辑。
- 不将不同分组的同名模型合并为一个最低价条目。
- 不新增管理端定价能力。
- 不在本次重构中引入服务端分页或搜索接口。
- 不直接计算“节省百分比”；官方价和本站价币种不同，缺少统一比较口径时该数字可能误导用户。

## 页面信息架构

### 顶部工具栏

顶部工具栏提供以下控制项：

- 统一搜索：匹配渠道名、渠道描述、分组名和模型名。
- 平台筛选：只显示选中平台下的渠道和分组。
- “仅看有定价”开关：隐藏未配置定价的模型。
- 刷新按钮：重新获取渠道与用户专属倍率。

搜索模型时，渠道导航只保留包含匹配模型的渠道；详情区只保留匹配的分组和模型，并自动展开相关分组。

### 桌面端双栏

桌面端使用响应式双栏布局：

- 左栏宽度约 280px，作为可滚动、吸顶的渠道导航。
- 每个渠道项显示渠道名、平台、可用分组数和可见模型数。
- 当前渠道使用清晰的选中态，并保留键盘焦点样式。
- 右栏显示当前渠道描述、平台以及按分组组织的价格表。
- 初次进入默认选择当前筛选结果中的第一个渠道。
- 当前选择被筛选掉时，自动选择新的第一个结果；无结果时进入独立空状态。

### 分组区

渠道详情按用户可访问分组分区。每个分组头部固定展示：

- 分组名称与平台主题色。
- 公开或专属状态。
- 标准或订阅类型。
- 默认倍率与用户专属倍率；存在专属倍率时明确展示生效值。
- 高峰时间窗口与高峰倍率。

同名模型存在于不同分组时分别保留在各自分组中，不跨分组去重。

## 价格展示

### 桌面价格表

每个分组使用价格表而非模型标签。核心列为：

1. 模型与计费方式。
2. 官方价。
3. 本站价。
4. 生效倍率。
5. 详情展开控制。

官方价格使用中性灰色，本站价格使用品牌强调色。两个价格区域始终同时可见，币种和单位不得省略。

### Token 模型

Token 模型主行固定展示：

- 官方输入价与官方输出价，单位为美元/1M Token。
- 本站输入价与本站输出价，单位为人民币/1M Token。
- 当前生效倍率。

缓存写入、缓存读取、图片输入和图片输出等次要价格放在展开详情中。

### 按次与生图模型

按次和生图模型不使用 Token 列，主行直接展示：

- 官方每次或每张价格。
- 本站每次或每张价格。
- 当前生效倍率或生图独立倍率。

计费方式和单位必须在价格附近明确标注，避免不同量纲被误读。

### 阶梯定价

存在阶梯价格时，主行使用“起”标识，并展示第一档的官方价与本站价。展开详情按配置顺序列出所有 Token 区间、输入价、输出价和按次价。区间标签优先使用管理员配置的 `tier_label`，否则由上下限生成。

### 高峰价格

高峰规则存在时，分组头部显示时间窗口与高峰倍率。模型详情同时给出常规本站价和高峰本站价，避免用户只看到常规价格后误判实际扣费。高峰时区继续使用服务器时区标签。

### 未配置定价

未配置定价的模型使用明确的“暂未定价”状态，不再通过悬浮层展示。启用“仅看有定价”后，这些模型从结果中隐藏；若某分组因此无模型，则整个分组隐藏。

## 移动端设计

移动端不保留狭窄的左侧导航：

- 页面顶部使用紧凑吸顶工具栏，包含渠道选择、模型搜索和筛选入口。
- 点击渠道选择打开底部抽屉；抽屉内支持搜索，并显示渠道平台、分组数和模型数。
- 选择渠道后关闭抽屉，主体全宽展示该渠道。
- 分组使用折叠面板，第一个分组默认展开，其余分组默认折叠。
- 搜索命中的分组自动展开。

移动端模型使用全宽价格卡。卡片顶部显示模型名、计费方式和倍率；主体以左右两列固定对比官方价和本站价。缓存、阶梯和高峰价格在卡片内部展开，行为与桌面价格行一致。

所有触控目标最小高度为 44px，不使用 hover 作为唯一信息入口，不产生页面级横向滚动。

## 视觉方向

页面采用“精密价格目录”风格，延续现有 Passion API 品牌色、平台色和明暗主题：

- 页面主体保持克制的浅色卡片与清晰边界，不使用大面积装饰渐变。
- 平台色只用于渠道选中态、分组边缘和小型徽章，避免与本站价格强调色竞争。
- 本站价使用最强视觉层级，官方价作为对照使用较弱层级。
- 金额使用等宽数字和 tabular numerals，保证纵向比较整齐。
- 通过留白、分组标题和价格分区建立层级，不依赖大量彩色标签。
- 暗色主题保留相同信息层级和足够对比度。

## 数据流与状态

### 数据来源

继续并发加载：

- `/channels/available`：渠道、平台、分组、模型及基础定价。
- `/groups/rates`：用户专属倍率。
- 公共设置中的 `available_channels_price_cny_multiplier`：本站人民币换算比例。

本次设计不要求修改接口契约。

### 统一视图模型

前端新增纯函数或 composable，将接口数据规范化为共享视图模型。视图模型负责：

- 解析渠道、平台、分组与模型层级。
- 计算默认倍率、用户专属倍率和高峰倍率。
- 计算官方价、常规本站价和高峰本站价。
- 区分 Token、按次、生图和阶梯计费。
- 生成渠道与分组的可见模型数。
- 执行搜索、平台筛选和有价筛选。

桌面价格表、移动价格卡和渠道导航只消费规范化结果，不各自重复价格计算。

### 选择状态

页面维护：

- 当前渠道 ID（由稳定的渠道键标识）。
- 搜索词。
- 平台筛选值。
- 仅看有定价开关。
- 已展开分组与模型详情。

数据刷新时尽量保留当前选择和滚动位置。仅当当前渠道不再存在于结果中时，才切换到第一个可用渠道。

## 加载、错误与空状态

- 首次加载使用左右布局对应的骨架屏。
- 后续刷新保留现有内容并静默更新，只让刷新图标显示忙碌状态。
- 渠道接口失败时显示带重试按钮的错误状态。
- 用户专属倍率获取失败时继续展示默认倍率，同时在页面内提示“暂未获取专属倍率”，不得静默伪装成最终实际价。
- 区分无可用渠道、筛选无结果、分组无模型和模型未定价四种状态。
- 刷新失败不清空上一次成功数据。

## 可访问性

- 渠道导航使用可键盘操作的列表或 tab 语义，并声明选中状态。
- 分组和模型详情使用真实 button，提供 `aria-expanded` 与受控区域关联。
- 渠道抽屉打开后管理焦点，关闭后返回触发按钮。
- 价格标签包含币种、单位和输入/输出含义，不能只用颜色区分。
- 亮色与暗色主题中的正文、边界、强调价格和禁用状态满足可读性要求。

## 测试策略

### 价格视图模型单元测试

- 默认倍率和用户专属倍率。
- 常规倍率和高峰倍率。
- Token 输入、输出、缓存与图片输入输出。
- 按次、生图及生图独立倍率。
- 阶梯价格和自动区间标签。
- 未定价模型。
- 同名模型跨分组保持独立。
- 搜索、平台筛选和仅看有定价。

### 组件测试

- 桌面双栏默认选择、渠道切换和选择失效回退。
- 官方价与本站价固定渲染。
- 分组、模型详情展开和键盘交互。
- 移动渠道抽屉、分组折叠与搜索自动展开。
- 加载、刷新失败、倍率降级和所有空状态。

### 视觉与响应式验证

- 390px、768px 和 1440px 三档视口。
- 亮色和暗色主题。
- 长渠道名、长分组名、长模型名和大量模型数据。
- 页面级无横向溢出，底部抽屉不超出安全区域。

## 发布与回滚

该重构只替换用户侧展示组件并复用现有接口，适合蓝绿部署。旧的 `AvailableChannelsTable` 在新页面验证完成后再移除；发布前保留清晰的组件级回滚边界。若线上出现展示问题，可回滚前端版本，不影响计费与网关请求。
