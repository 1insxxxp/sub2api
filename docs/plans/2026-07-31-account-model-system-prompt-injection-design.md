# 指定账号模型系统提示词注入设计

## 背景与目标

为账号管理增加模型级系统提示词配置，使管理员能够针对“指定账号 + 指定真实上游模型”注入一段纯文本系统提示词。该能力主要用于为酒馆（SillyTavern）等角色扮演客户端提供模型级行为预设，同时保留客户端自身携带的角色卡、世界书和系统提示词。

首版支持 OpenAI、Claude、Gemini 三类文本上游账号，只提供 `prepend` 语义，不支持覆盖、后置、通配符、变量模板或条件表达式。

## 范围

### 包含

- 为单个账号配置零条或多条“真实上游模型 → 系统提示词”规则。
- 在账号调度和模型映射完成后，按账号 ID 与映射后的真实模型名精确匹配。
- 支持 OpenAI Responses、OpenAI Chat Completions、Claude Messages 和 Gemini GenerateContent 形态的文本请求。
- 在管理端账号编辑界面新增配置、校验和保存能力。
- 保证重试不重复注入，上游账号切换后按新账号重新计算。

### 不包含

- 全局、分组或 API Key 级别的提示词规则。
- 模型名通配符或正则表达式。
- 多提示词块、模板变量、条件表达式和动态内容。
- `append`、`replace` 或管理员可选合并模式。
- 图片、视频、Embedding 等非文本请求。
- 真正的模型微调、LoRA 或训练能力。

## 方案选择

### 采用：账号表独立 JSONB 字段

在账号表增加独立的 JSONB 配置字段，逻辑结构如下：

```json
{
  "gpt-5.4": "系统提示词 A",
  "claude-opus-5": "系统提示词 B"
}
```

该配置属于账号业务属性，不放入 OAuth/API Key `credentials`。独立字段使管理接口、缓存失效、数据校验和未来扩展保持清晰，同时避免账号凭据更新、脱敏或导入导出意外影响提示词规则。

未采用的方案：

- 存入 `credentials`：迁移较少，但会把非凭据业务配置与认证信息耦合。
- 独立规则表：扩展能力更强，但首版只有模型到纯文本的一对一映射，成本过高。

## 数据模型与管理接口

账号模型新增一个映射字段，例如 `ModelSystemPrompts map[string]string`，数据库字段使用非空 JSONB，默认值为 `{}`。现有账号迁移后不产生任何行为变化。

管理员账号详情、创建和更新 DTO 支持该字段；普通用户接口不返回此配置。账号更新时整体替换规则集合，确保在界面删除的规则不会残留。配置变更必须触发现有账号运行时缓存失效。

保存时执行以下校验：

- 模型名和提示词去除首尾空白后不能为空。
- 同一账号不能配置重复模型名。
- 模型名使用精确字符串，不做别名展开或通配符解析。
- 单条提示词最大 32 KiB。
- 空规则集合归一化为 `{}`。

## 管理界面

在“账号管理 → 编辑账号”增加“模型系统提示词”区域。管理员可添加、编辑和删除多条规则，每条规则包含：

- 真实上游模型名称。
- 纯文本系统提示词。

界面说明需明确：模型名称应填写账号模型映射完成后的真实上游模型，而不是客户端使用的公开别名。首版合并模式固定为“前置”，不展示合并模式控件。

## 请求处理流程

每次文本请求采用以下顺序：

1. 解析客户端请求模型。
2. 调度并确定具体上游账号。
3. 完成账号模型映射，得到真实上游模型。
4. 从所选账号配置中精确查找该真实模型。
5. 命中非空规则时执行一次协议对应的 `prepend` 改写。
6. 继续现有协议转换、签名和上游发送流程。

注入必须基于最终选中的账号执行。如果请求发生上游账号切换，必须从未注入的原始/规范化请求重新构造，并按新账号的规则重新计算；不得携带前一个账号的提示词。单个账号内的网络重试复用已改写请求，不得再次叠加。

## 协议改写规则

### OpenAI Responses

当 `instructions` 已存在时：

```text
<注入提示词>\n\n<原 instructions>
```

不存在时创建 `instructions`。输入消息和其他请求字段保持不变。

### OpenAI Chat Completions

在 `messages` 数组最前面插入新的 `system` 消息。已有 `system`、`developer`、用户消息及其结构保持原样。

### Claude Messages

- `system` 为字符串时，使用“注入提示词 + 两个换行 + 原 system”。
- `system` 为 blocks 时，在数组最前面插入一个 text block。
- 原有 block、`cache_control` 和其他扩展字段保持原样。

### Gemini GenerateContent

在 `systemInstruction.parts` 最前面插入一个 text part；字段不存在时创建标准 `systemInstruction` 结构。原有 parts 保持原样。

## 共享组件与接入点

后端提供共享的规则匹配和协议改写组件，输入至少包含账号配置、映射后的模型、请求协议和请求体，输出改写后的请求体及“是否应用”标记。OpenAI、Claude、Gemini 各自的转发路径在模型映射完成后、最终协议转换或上游请求构造前调用该组件。

共享组件只负责纯函数式匹配和请求改写，不查询数据库，也不记录提示词正文。账号配置随现有调度快照/账号对象进入热路径，避免每次请求额外访问数据库。

## 非文本请求识别

注入仅在已知文本生成端点和文本模型转发路径执行。图片、视频、Embedding、Moderation、音频及批量非文本任务不进入注入组件。不能只依赖模型名猜测文本能力，应优先由当前路由/端点类型决定。

## 错误处理与安全

- 非法配置在管理员保存时返回明确的字段错误，不进入运行时。
- 请求体解析或改写失败时终止该次请求，沿用相应协议的错误响应和现有错误记录机制，不静默跳过配置。
- 普通日志只记录账号 ID、真实上游模型和是否应用，不记录系统提示词正文。
- 管理端接口沿用管理员权限校验，普通用户不可读取提示词配置。
- 提示词会增加输入 Token；账单和用量统计继续以上游返回值为准。

## 测试策略

### 后端

- 数据库迁移默认值及账号仓储读写。
- 账号创建、详情、更新、清空规则和缓存失效。
- 空模型、空提示词、重复模型和超长提示词校验。
- 三类协议在无原系统提示词与已有系统提示词时的精确改写结果。
- 模型映射后命中，客户端公开别名不直接作为匹配依据。
- 相同真实模型在其他账号不注入。
- 单账号重试不重复注入。
- 上游账号切换后移除旧账号注入并按新账号重新计算。
- 非文本路由不注入。
- 日志和普通用户 DTO 不泄露提示词正文。

### 前端

- 账号编辑页面新增、修改和删除规则。
- 重复模型、空字段和长度限制提示。
- API 序列化、回填和清空规则。
- 不同账号类型均显示并保存相同配置结构。

### 本地验证

- 运行后端相关包单元测试与数据库迁移测试。
- 运行前端目标单测、类型检查和构建。
- 使用本地三类测试账号分别验证有规则、无规则和模型映射场景，检查实际发送到上游的请求体，同时确保调试输出不包含完整提示词。

## 成功标准

- 管理员能为任一 OpenAI、Claude 或 Gemini 文本账号保存多个模型提示词规则。
- 只有选中该账号且映射后的真实模型精确命中时才执行一次 `prepend`。
- 酒馆客户端原有角色卡、世界书和系统提示词保持存在并位于注入内容之后。
- 其他账号、其他模型和非文本请求行为完全不变。
- 重试、故障切换、缓存和日志行为符合上述约束。
