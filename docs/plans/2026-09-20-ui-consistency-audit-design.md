# 管理端 UI 统一审计与分阶段改造设计

## 背景

项目已经有明确的视觉基准：API 密钥页、`workspace-tokens.css`、`admin-workspace.css` 和 `user-workspace.css` 共同定义了中性半透明表面、细边框、内侧高光、柔和阴影、紧凑间距、品牌蓝主操作和移动端 H5 规则。实际页面仍有大量旧样式，导致同一工作流中的卡片、表格、分页、弹窗、提示和状态展示不一致。

本次工作先完成管理员端的系统化统一，再把验证过的公共组件和规则迁移到用户端。保留现有接口、权限、业务字段和数据流，不借 UI 改造改变业务行为。

## 审计结论

### 公共组件

- `DataTable` 的移动骨架、空状态和部分桌面表格分支仍使用硬编码白底、旧灰阶和大圆角。
- `Pagination` 已通过管理员外观上下文默认切换到 `compact`，但默认外观和脱离该上下文的页面仍保留白底灰边框；需要补齐上下文覆盖和移动端边界测试。
- `BaseDialog` 已有 neutral 外观，但复杂弹窗在移动端仍按居中桌面弹窗布局，底部操作和长内容容易拥挤。
- tooltip 的触屏行为和视口边界不统一。部分页面只依赖 hover 或原生 `title`，窄屏可能出屏或无法访问。

### 管理员页面

- 仪表盘统计卡图标仍大量使用彩色块，和中性卡片表面冲突。
- 渠道监控、审计日志、抽奖、插件、分组表单仍有大圆角白卡、层层套卡或大面积强调色。
- 列表页的表格、筛选、分页和空状态没有完全走统一的工作区材质。
- 部分页面仍使用 `transition-all` 或只提供 hover 反馈，缺少统一的 reduced-motion 和键盘焦点行为。

### 移动端

- 费用拆分和说明 tooltip 只支持 hover 或固定 `left-full`，触屏不可用且可能出屏。
- 批量生图详情保留固定宽表格，核心字段在手机上需要横向拖动。
- 仪表盘筛选和统计卡在 320–375px 宽度下容易挤压。
- 可用渠道列表和长错误/提示文本存在裁切或横向溢出风险。

## 目标

1. 管理员端的公共组件使用同一套材质、间距、圆角、状态色和焦点规则。
2. 管理员仪表盘、账号、用户、分组、渠道五个高频入口完成第一批页面级迁移。
3. 所有第一批页面在 320px、375px、390px、640px 和桌面宽度下可读、可操作，不依赖 hover 才能获得关键内容。
4. 组件和页面支持深色模式、`prefers-reduced-motion` 和键盘导航。
5. 改造可以分批合并和回滚，不影响现有 API、权限、计费、筛选和提交逻辑。

## 非目标

- 不做全局一次性替换 Tailwind 类名。
- 不重写业务接口、状态管理或路由权限。
- 不在第一阶段重新设计低频页面的业务流程。
- 不把所有页面强行改成完全相同的卡片；表格、表单、详情和复杂工具保留各自的信息密度。

## 设计方向

### 令牌和材质

继续使用 `workspace-tokens.css` 作为颜色、边框、分隔线、控件底色和阴影的来源。页面级样式只组合这些令牌，不再直接写白色/灰色硬编码作为默认表面。统一圆角以 6–8px 为主，主要操作使用品牌蓝，厂商色只作为小图标或状态点缀。

### 公共组件优先

先处理 `DataTable`、`Pagination`、`BaseDialog`、tooltip/说明入口和列表工具栏。公共组件完成后，页面只需接入明确的 appearance 或 workspace 类，减少每页重复修复。

### 页面迁移顺序

第一批按以下顺序执行：

1. 管理员仪表盘：统计卡、筛选工具栏、图表和空/加载态。
2. 管理员账号：账号卡、批量操作、错误详情和移动端操作区。
3. 管理员用户与分组：列表、筛选、选择卡、表单分区和详情弹窗。
4. 管理员渠道与渠道监控：表格、状态、模型列表、长文本和监控结果。
5. 其余管理员页面：审计、插件、抽奖、支付、设置和低频工具。

用户端第二阶段复用第一阶段的公共组件和移动端规则，再按仪表盘、使用记录、渠道状态、支付和低频页面推进。

### 移动端规则

- 关键说明使用可点击、可聚焦的 tooltip 或详情入口，不能只依赖 hover/title。
- 长文本使用换行、折叠或详情展开，禁止通过 `overflow-x-hidden` 静默裁切主要信息。
- 工具栏和弹窗 footer 在窄屏按纵向或两列稳定布局，触控目标至少 44px。
- 统计卡按信息重要性重排，避免为了保持桌面两列而压缩数字和标签。
- 复杂表格在手机上使用详情卡或可展开行，保留横向滚动作为次要兜底。

## 验证方式

- 公共组件单元测试覆盖外观上下文、加载/空状态、键盘焦点和移动布局。
- 页面测试保留现有业务断言，并新增关键 class/布局断言，避免只测试快照。
- 使用 320/375/390/640px 和桌面宽度做浏览器视觉检查，覆盖浅色、深色、减少动态效果。
- 每一批改动完成后运行受影响的 Vitest 测试、类型检查和构建；只在验证通过后继续下一批。

## 取舍

选择“令牌和公共组件优先、按页面分批迁移”，因为它能在保持业务稳定的同时减少重复样式，先解决用户最容易感知的表格、分页、弹窗、提示和移动端问题。全局替换速度更快但回归风险高，逐页重做则会让多套风格长期并存。
