# 分组模型按次计费设计

## 目标

允许管理员为指定分组中的指定玩家请求模型配置固定的 USD 单次价格。命中规则的成功请求只收取一次固定费用，不再按 Token 金额计费；未配置规则的模型继续使用现有 Token 计费。

## 已确认规则

- 配置粒度为 `分组 + 玩家请求模型名`。
- 模型名精确匹配、大小写不敏感，不做模型家族模糊匹配。
- 按次计费完全替代 Token 计费，不与 Token 费用叠加。
- 仅成功完成并进入现有用量结算流程的请求扣费。
- 本地拦截、调度失败、网络错误、上游错误和超时不扣费。
- Token 使用量仍写入用量日志，仅用于统计。
- 未配置按次价格的模型回退到现有 Token 计费。
- 价格以 USD/次保存，前端沿用现有汇率换算显示人民币。
- 模型映射和账号切换不改变价格，计费始终匹配玩家请求的模型名。

## 方案选择

### 采用：复用渠道模型定价

现有渠道模型定价已经支持：

- 分组与渠道关联，且每个分组最多属于一个渠道；
- `billing_model_source=requested`；
- 模型级 `billing_mode=per_request`；
- `per_request_price`；
- 统一余额/订阅结算、幂等扣费和用量日志；
- `billing_mode=per_request` 的后台与用户端展示。

因此不新增分组 JSON 字段或独立定价表，避免形成第二套定价优先级。管理员通过渠道定价关联目标分组，并为单个模型配置按次价格。

### 不采用：分组表 JSON 配置

虽然编辑入口直接，但会与渠道定价重复，难以定义两套配置冲突时的优先级，也不利于查询和审计。

### 不采用：独立分组模型定价表

数据结构清晰，但与现有 `channel_model_pricing` 高度重复，迁移、缓存和管理界面的成本不合理。

## 数据与解析

不新增数据库迁移。沿用：

- `channels.billing_model_source = requested`
- `channel_groups(channel_id, group_id)`
- `channel_model_pricing.models`
- `channel_model_pricing.billing_mode = per_request`
- `channel_model_pricing.per_request_price`

定价解析使用 `ModelPricingResolver.Resolve`：传入玩家请求模型和分组 ID。命中渠道按次规则时返回 `BillingModePerRequest`；未命中时继续解析 LiteLLM 或 fallback Token 价格。

## 请求与扣费流程

1. 客户端请求模型 `requested_model`。
2. 渠道映射和账号映射可以把请求转发到其他上游模型。
3. 成功响应产生最终 `ForwardResult` 后进入 `RecordUsage`。
4. 当渠道 `billing_model_source=requested` 时，计费模型固定为原始请求模型。
5. `ModelPricingResolver` 按 `group_id + requested_model` 查找价格。
6. 命中 `per_request` 时，单次价格乘请求次数（文本请求固定为 1），完全忽略 Token 金额。
7. 应用现有分组/用户倍率后，通过现有事务和幂等机制扣费。
8. 用量日志保留 Token 数量，并写入 `billing_mode=per_request` 与固定费用。

失败请求不会进入成功后的用量结算路径，因此不产生按次扣费。

## 管理界面

复用“渠道定价”页面：

- 关联一个或多个同平台分组；
- 将计费模型来源设为“请求模型”；
- 添加模型定价条目；
- 选择“按次计费”；
- 输入一个或多个精确模型名；
- 输入 USD/次价格。

界面需要把该模式的语义说明清楚：按次价格替代 Token 费用，只有成功请求扣费，未配置模型继续按 Token 计费。无需在分组编辑页复制完整定价编辑器。

## 错误处理

- `per_request` 条目没有默认价格或有效区间时拒绝保存。
- 单次价格小于 0 时拒绝保存；0 允许表示免费模型。
- 同一渠道、平台、模型出现冲突规则时沿用现有冲突校验。
- 定价缓存更新失败时保存操作返回错误，不让管理员误以为新价格已生效。
- 扣费事务失败时沿用现有用量结算错误处理和请求幂等保护。

## 测试策略

- 定价解析：精确请求模型命中按次价格，大小写不敏感。
- 回退：未配置模型仍按 Token 计费。
- 模型映射：请求模型和上游模型不同时，使用请求模型价格。
- 金额：按次费用替代 Token 费用，Token 数量仍保留。
- 成功边界：成功响应扣一次；上游 4xx/5xx、网络错误、超时和本地拒绝均不扣费。
- 协议覆盖：OpenAI Chat/Responses、Anthropic Messages、Gemini 文本路径。
- 前端：按次模式校验、说明文本和序列化请求正确。

## 非目标

- 不支持按用户、API Key 或账号单独覆盖单次价格。
- 不支持固定费与 Token 费用叠加。
- 不支持失败请求收费。
- 不新增人民币价格存储。
- 不新增模型通配符作为本功能的推荐配置方式。
